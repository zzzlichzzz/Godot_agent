# Работа с проектом через Godot Agent — D119

Статус пунктов из [отчёта от 2026-11-26](ai-usage-issues.md). Пользователь проверил диалог в D121 и предоставил `chat.txt`. Исправления по результатам этого прогона установлены в [D122](adr/0097-panel-read-consent.md).

| Пункт | Что изменилось | Что осталось |
|---|---|---|
| 1.1 Стартовый контекст | Панель D122 не прикладывает карту или данные редактора; модель запрашивает дерево, сцену или описание проекта. Вне панели сохранена карта D119. | Описание опционально: создайте `AGENT_ARCHITECTURE.md` в корне проекта. Если нет отдельного вклада секции, агент вернёт до 1 200 символов из этого файла. |
| 1.2 `list_files` | Оба цикла вызывают публичный `tree`; `dir` и `subdir` — альтернативные имена аргумента. | На больших проектах сужайте `subdir` при `truncated`. |
| 1.3 `gather_context` | Оба цикла передают `sections` и `path` в `context`. Промпт не обещает неподдерживаемые флаги. | Это не перенос монолитного native-сборщика: live-данные зависят от реально подключённых вкладов. |
| 1.4 Анализ символов в чате | `find_symbol_usages` и `analyze_rename` доступны в обоих циклах. | При неоднозначности укажите путь или точное объявление. |
| 1.5 Аргументы чтения | Один преобразователь сохраняет аргументы чтения, функций, поиска, библиотекаря и сцен. Выдача ограничена общим бюджетом; чтение можно продолжить. | Большие запросы дробите на страницы; переполненный результат не передаётся модели как обрезанный JSON. |
| 1.6 `copy_file` | Убрано обещание этого действия из промпта обоих циклов. | Само действие не добавлено. |
| 1.7 `inspect_runtime` | Убрано обещание из промпта обоих циклов. | Снимок рантайма через публичный инструмент не реализован. |
| 1.8 Протокол чата | Один поддерживаемый промпт описывает текстовый формат и подтверждение записи. С D121 браузер отправляет инструкции вместе с первым запросом, а полный текст сцены не прикладывается. | Нативные вызовы инструментов провайдера не добавлены; `agent_action`, `===DONE===` и проверки ответов остаются. |
| 2.1 Публичное дерево | `tree` зарегистрирован и проверен через CLI и MCP. | Глубина, число файлов, узлов и просмотренных записей ограничены. |
| 2.2 Чтение диапазона | `read` принимает `start_line`/`end_line` (с 1, включительно) и абсолютный `offset` (с 0, в символах после нормализации перевода строк). | Передавайте `next_offset` с теми же границами. Страницы не фиксируют версию файла между вызовами. |
| 2.3 Фильтры поиска | Добавлены `include_rel_prefixes`, `only_exts`, ограничение выдержки и постраничная выдача по группам совпадений. | Поиск по-прежнему буквальный; регулярных выражений и снимка индекса на время пагинации нет. |
| 2.4 Локатор объявления | `usages` и `analyze_rename` могут найти уникальное видимое объявление по виду и имени, в том числе внутри одного `declaration_path`. | При неоднозначности или неполной области автоподбора нет. Для записи нужен точный локатор. |
| 3.1 Типизированные правки | `assistant_plan.operations` принимает создание, точечную замену и перемещение текстовых файлов. Выдаёт предпросмотр, не применяя его. | Структурные операции над сценами, ресурсами и настройками не получили типизированную схему в этой ветке. |
| 3.2 Профиль редактора | Задокументировано, откуда действующая панель получает снимок редактора. | MCP и HTTP всё ещё используют `cli`; модульный мост не подключён. Нужна отдельная проверка в живом Godot. |
| 3.3 Обнаружение в MCP | `initialize` объясняет, с каких инструментов начать и как подтверждать правки; имена совместимы. | `tools/list` остаётся плоским; описания не унифицированы по языку. |
| 4.1 Параллельные контуры | `AGENTS.md` и [карта архитектуры](architecture.md) показывают рабочие точки входа и альтернативный мост. | Реализации не объединены, точка входа плагина не переключена. |
| 4.2 Две TODO-заглушки | Удалены неиспользуемые `channels/mcp/handlers.py` и `runtime/profiles.py`. | Обработка MCP и выбор профиля остались в действующих файлах. |
| 4.3 Пины native | Изменения промпта и ожидания DeepSeek сделаны в поддерживаемом коде вне пинов. | Пины сохранены; их снятие не требуется для этой задачи. |
| 4.4 Старт работы | [ADR-0094](adr/0094-task-scoped-onboarding.md) заменяет чтение всех стартовых документов навигацией по задаче. | Правила безопасности и проверки перед сдачей сохраняются. |

Для первого прохода по проекту: `tree` → `search` или `functions` → `read` по нужным строкам. Для правки: `assistant_plan` → показать diff → `assistant_confirm` только после явного одобрения пользователя. Точные схемы — в `contract/capabilities/` и `tools/list`.
