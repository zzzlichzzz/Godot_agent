# Архитектура Godot Agent

Код плагина живёт в `addons/godot_agent/`; пути ниже отсчитываются от этой папки. Главное разделение: **канал доставляет запрос, модуль определяет поведение, адаптер выполняет IO**. Если для исправления одного инструмента приходится менять его логику и в панели, и в MCP, сначала найдите общего владельца.

## Как запрос доходит до кода

| Откуда | Маршрут |
|---|---|
| Док Godot | [`plugin.cfg`](../plugin.cfg) → [`editor/native/agent_entry.gd`](../editor/native/agent_entry.gd) → панель и `agent_server_link.gd` → локальный HTTP-сервер. Точка входа EXE — [`exe_entry.py`](../python/channels/http/exe_entry.py). Панель получает контекст от редактора. |
| Чат панели | [`channels/http/`](../python/channels/http/) связывает запрос, чат и решение пользователя. [`runtime/http_services.py`](../python/runtime/http_services.py) подключает адаптеры чата; [`modules/assistant/write/`](../python/modules/assistant/write/) ведёт ход и готовит изменения. Доставка в браузер/API и разбор ответов находятся в `substrate/`. |
| CLI и MCP | [`channels/cli/main.py`](../python/channels/cli/main.py) и [`channels/mcp/stdio.py`](../python/channels/mcp/stdio.py) → [`runtime/bootstrap.py`](../python/runtime/bootstrap.py), профиль `cli` → диспетчер → тот же владелец инструмента. MCP работает по stdio. Доступ к открытому редактору этим не подразумевается. |

[`plugin.gd`](../plugin.gd), `editor/core/lifecycle.gd` и `editor/bridge/` реализуют отдельный модульный мост. Он не загружается вместо `agent_entry.gd`. Исправление в нём само по себе не изменит поведение дока.

## Границы модулей

| Слой | Ответственность |
|---|---|
| `python/kernel/`, `python/formats/` | Общие типы, ошибки, пути и планы; отдельно — разбор форматов без диска и запущенного Godot. |
| `python/modules/<область>/<фича>/` | `module.py` объявляет манифест и зависимости; `tools*.py` описывают контракт; `app.py` оркестрирует сценарий. `domain/` — чистая логика. Нужный модулю IO описывается портом на стороне потребителя. |
| `python/substrate/` | Реализации портов: файлы проекта, Godot, хранилища, провайдеры. У `substrate` нет права менять публичный контракт в обход владельца. |
| `python/runtime/`, `python/protocol/` | Первый собирает профиль и связывает порты; второй регистрирует инструменты, валидирует запросы и передаёт их обработчикам. Бизнес-правила сюда не выносятся. |
| `python/channels/`, `editor/` | Транспорт, интерфейс и примитивы редактора. Не дублируют реализацию инструмента. |

**Один инструмент — один владелец.** Модуль может объявить несколько `provides_tools`; другие добавляют вклад через `contributes_to`. Общение между модулями — через публичную границу и объявленную зависимость, не через чужой `domain/`. Неисправный модуль отключается вместе с зависимыми; независимые должны остаться доступны. Известное, но недоступное имя даёт `unavailable`, неизвестное — `unknown_tool`. См. [контракт активации](adr/0098-module-activation.md) и [проверку композиции](../tests/py/integration/test_module_composition.py).

**Схема инструмента.** Источник — `ToolSpec`, артефакт для клиентов — [`contract/capabilities/`](../contract/capabilities/). После изменения дескриптора: `python tools/gen_contract.py --write`, затем `--check`. Словарь примитивов редактора — отдельный контракт. Имена действия в чате (`edit_scene`, `rename_symbol`) и публичного инструмента (`assistant_plan`) могут различаться. [Подробности](adr/0006-kontrakt-istochnik-i-artefakt.md).

## Где проходит граница записи

1. Запрос чтения в панели привязан к чату и одноразовому билету. Выбор моделью текста или варианта ответа не даёт полномочий менять проект. [Решения пользователя в чате](adr/0099-chat-action-consent.md).
2. `assistant_plan` или `assistant_turn` подготавливает неизменяемый предпросмотр. Для структурных изменений Godot работает с целью и её зависимостями во **временной копии**; проект на диске в этот момент не меняется. Скриптовые цели/зависимости и autoload не исполняются ради предпросмотра.
3. `assistant_confirm` сверяет план и digest. Только штатный исполнитель записывает решение в журнал **до файловых эффектов** и применяет согласованные байты. При отказе записи нет. `assistant_rollback` сверяет текущее состояние; откат не затирает последующую чужую правку. [Протокол записи](adr/0005-tranzakcionnyj-protokol.md).
4. В рабочем профиле файлы проекта читаются и публикуются через `GodotFiles` / `GodotWriter`, использующие `FileAccess` / `DirAccess`. Python управляет политикой, планом, внешним журналом и резервными копиями. Прямой Python-доступ в тестовом профиле не является запасным путём для рабочего. [Решение о файловом IO](adr/0100-project-file-io.md).

Ограничения путей, процессов, сети, секретов и внешнего профиля проверяются отдельно от бизнес-логики: [инварианты и их тесты](security/invariants.md). Перед сдачей исправления используйте [проверки проекта](README.md).
