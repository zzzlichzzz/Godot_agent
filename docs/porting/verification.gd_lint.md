**Статус:** этап `7`, `ported` (2026-10-29; перенос завершён, готов к независимому аудиту)
**Обновлено:** `2026-10-29`

## Цель

Read-инструмент `gd_lint` проверяет один `.gd` внутри проекта и возвращает
упорядоченные находки как данные (`code`, `line`, `message`), `truncated` и
число исходных байтов `checked_bytes`. Никаких автоисправлений, запуска кода,
Godot или агрегатора `check`.

## Спецификация

- ToolSpec: `gd_lint`, вход `{path}`, результат `{findings,truncated,checked_bytes}`,
  `effects="read"`, idempotent; PathPolicy и типизированные отказы.
- Порт чтения исходных байтов через существующий `fs.read_raw`, Protocol в модуле;
  композиция уже есть в `runtime/bootstrap.default_ports`, его код менять не нужно.
- Размер: существующий `kernel.limits.READ_TEXT_MAX_BYTES = 4194304` (4 MiB),
  объявляется в ToolSpec.limits; BOM/CRLF сохраняются при декодировании и учёте байтов.
- Алгоритм и порядок/дословные сообщения эталона не исправляются. Только один
  lint-сканер; `formats/**`, другие механики и контракт моста не меняются.
- `domain/` без IO; входные данные не исполняются; результат не содержит команд.

## F1 / C.10 — отдельная дельта принятого файлового декодирования

2026-10-31 пользователь выбрал ремонт BOM false-clean. Предыдущая фиксация
«utf-8 без stripping» в этом листе относится к исторической C.2 и не считается
верным файловым паритетом: эталон read_project_file использует utf-8-sig.
Пересняты018/019/**035-bom_only** реальным `_check_one_path`; previous_expect
и reference_text_messages сохраняют старые pure-text наблюдения. Публичный
lint_gdscript(text) не изменён; check(raw) применяет shared source_text decoder,
считая checked_bytes по исходным bytes. Текстовый oracle-тест остаётся отдельно.

Дельта: `docs/porting/verification.bom.md`, ADR-0008. Собственная приёмка ещё
не выполнена; исторический stage7 C.2 не переименовывается/не отменяется.
