# assistant.write — T-B

### D129 — подтверждение живого ввода AI Studio

До отправки сравнить черновик панели с видимым полем выбранной страницы. HTTP 200 с `applied:false` не подтверждает ввод. Если поле ещё грузится, передать актуальный текст после его появления без дополнительной клавиши и без `/chat`. Проверить скрытое поле, замену поля при перерисовке и отсутствие записи в другую вкладку. Время ответа модели измерять отдельно, после отправки.

Проверено в Godot и Chrome 158 на локальной форме: сначала поле отсутствовало, затем страница заменила его пустым после `input`. Без новой клавиши черновик появился в видимом поле; следующая многострочная правка сохранилась. Прозрачное поле и другая вкладка с тем же адресом остались пустыми. Отправок формы и вызовов `/chat` — ноль. Следующая проверка после установки — набрать текст в панели, увидеть его в рабочей вкладке AI Studio до отправки.

### D128 — открытие сохранений браузера

Различать открытие локальной истории и готовность страницы для продолжения. При отказе драйвера, общем URL нового чата вместо существующей переписки или недоступной странице показать историю и причину; не печатать и не отправлять в неподтверждённый чат. Для AI Studio сохранять адрес конкретной беседы только после проверенного перехода в той же вкладке. Не присоединяться к чужому процессу Chrome.

Проверено: пять вариантов открытия через HTTP; в Chrome 158 на локальной тестовой странице — отправка, сохранение адреса, отказы при другой вкладке, перенаправлении и несовпадении текста. Следующая проверка в рабочем аккаунте после установки — создать новый чат AI Studio, отправить вопрос и открыть тот же диалог из списка.

### D127 — AI Studio: версия инструкций и черновик

Сравнивать с теми же инструкциями панели, которые успешно ушли в браузер;
проверять новый чат, настоящий конфликт версий и отказ провайдера. Правка
черновика меняет только отличающийся диапазон в поле выбранного чата, без
отправки. Для `ask` строка — штатный результат; журнал хранит только исход.

Проверено через HTTP: новый чат не помечен устаревшим до и после успешной отправки; действительное расхождение версий отмечается. Один точный ответ сайта о недоступности модели стал ошибкой провайдера без повторной отправки, цитата той же фразы осталась обычным ответом. `search_project`, `read_function`, `list_scene`, `ask_librarian`, `gather_context` вернули данные после пяти отдельных разрешений на чтение. Изолированный Chrome сохранил неизменённый хвост при замене, вставке и удалении в середине многострочного черновика; отправок — ноль. Следующая живая проверка — правка в середине в своей вкладке AI Studio и повторное открытие списка чатов.

### D124 — сохранённый диалог панели

`/chats/open` восстанавливает поле `transcript` в `agent_chats.json`, а модульный
`/chat` возвращал ответ только клиенту. Критерий: отправить сообщения, создать
новый сервер с тем же внешним профилем и открыть тот же чат. Сохранять только
видимые реплики, с исходными ролями, без повторов запроса на продолжениях.
Сбой записи не должен терять уже полученный ответ или запускать его повторно.

Воспроизведено: при успешном ответе `transcript` оставался `[]`. Теперь завершённый
ход панели атомарно дописывается по ID фактически выбранного чата. Для продолжения
чтения записывается только новая реплика. Повторное открытие двух разных чатов
в новом экземпляре приложения, неявный первый чат, маскирование ключа и токена,
сбой записи без повторной отправки, восемь чтений без дубля запроса проверены
на временных профилях. Ранее незаписанные строки из памяти модели не импортируются.

Установленный D124 проверен двумя процессами с одним временным профилем:
одна отправка в локальный тестовый API → штатная остановка → новый процесс →
`/chats/open`. Текст пользователя и ответ вернулись в исходном порядке; открытие
не вызвало второй генерации. Следующая пользовательская проверка — открыть
свежий диалог из истории после перезапуска редактора.
