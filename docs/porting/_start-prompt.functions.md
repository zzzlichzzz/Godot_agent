## 2. Эталон: что там на самом деле (проверено, не пересказ)

Файл: `<эталон>/python/godot_tools/gd_functions.py` — 73 строки, из импортов только `re`.
Обе функции чистые: ни диска, ни Godot.

| Функция | Сигнатура | Что делает |
|---|---|---|
| `list_functions` | `(text) -> [names]` | имена всех функций в порядке объявления |
| `extract_functions` | `(text, names) -> (found, missing)` | `found`: `{name, snippet, start_line, end_line}` (нумерация с 1); `missing`: запрошенные, которых нет |

Распознавание одно: `^(\s*)(?:static\s+)?func\s+([A-Za-z_]\w*)\s*[(]` — то есть
`static func` функция, а `func_ready` без `(` — нет. Разбор **индентационный**, не AST:
тело — все строки с отступом глубже заголовка; пустые строки внутри тела его не обрывают,
хвостовые пустые обрезаются. В сниппет входят прилегающие сверху `#`-комментарии и
`@`-аннотации (подряд, вверх). При дубле имени берётся **первое** объявление.

Как это вызывалось: `tools/agent_bridge.py:516-529` (`names` есть → извлечение, нет →
список; вывод текстом: `path: …`, `functions (N): a, b`, `function: name (lines s-e)`,
`missing: name`; коды `RC_OK`/`RC_NOT_FOUND`) и `main.py:1072` (`read_function` в пакетном
чтении: `path` + `names|functions`). Ветка `--card` (`agent_bridge.py:495-515`,
`function_card.py`) — **не твоя**: это `code_intel.function_card`, отдельная механика.

## 5. Обязательные кейсы корпуса

1. список без `names`: порядок объявления, `_ready`/`_process` вперемешку с обычными;
2. `static func` попадает в список;
3. извлечение одной функции: `snippet` дословно, `start_line`/`end_line` верные;
4. несколько имён, часть отсутствует → `missing` с этими именами;
5. дубль имени (функция объявлена дважды) → берётся первое объявление;
6. прилегающие сверху `#`-комментарии и `@`-аннотации (`@tool`, `@rpc("any_peer")`) в сниппете;
7. пустые строки внутри тела сохраняются, хвостовые после тела — обрезаются;
8. вложенный `class Inner:` → `func` с отступом находится (regex разрешает отступ);
9. файл с BOM в начале;
10. файл с CRLF: номера строк и `snippet` не съезжают;
11. закомментированная функция (`# func fake():`) **не** находится;
12. путь не `.gd` (`.tscn`, `.txt`) и несуществующий путь → поведение как в эталоне
    (`not_found` или пустой результат — что покажет `expect`, то и фиксируй);
13. путь с `..` или абсолютный → `denied` (политика), не `internal`;
14. файл в `addons/` → по политике скрыт (как кейс 011 у поиска).

Если `test_gdscript_wiring.py` (41 КБ) на поверку окажется не про функции — **поправь
`tests-map.md`** и запиши это в лист. В прошлый раз триаж ошибся с `test_search_quality.py`,
и правильным поведением было исправить карту, а не подогнать кейсы.

## 6. Решения, которые обязан принять и записать

1. **`formats/gdscript.py` или домен?** Единый парсер `.gd` (см. `docs/mapping.md`, раздел
   «что дублировалось») ещё **не перенесён** и остаётся отдельной механикой. Здесь
   реализуется ровно индентационная логика эталона внутри `domain/core.py`. Когда появится
   `formats.gdscript`, эти функции переедут туда отдельным рефакторингом с двойным
   прогоном. Создать `formats/` сейчас = переносить две фичи сразу (нарушение R-08).
2. **Формат результата.** Эталон печатал текст, ты отдаёшь структуру. Это не отличие
   поведения, а разделение «домен — канал»: корпус снимается с функции эталона, а не с
   текста MCP. Запиши это в лист, чтобы следующий аудитор не искал мнимое расхождение.
3. **Не-`.gd` путь.** Решение принимается по `expect`, а не по вкусу: если эталон молча
   возвращал пусто — так и оставляй.
4. **Долг R-03** (`unknown_tool` вместо `unavailable`) — если по пути закроешь его на двух
   модулях, отметь строку в `PROGRESS.md` → «Долги» как закрытую с датой.
