# D137 — что перепроверить в панели Godot

Для проверки момента записи используйте обычное подтверждение (без «Разрешить всё»). Запросы ниже можно отправлять в Qwen по одному. Если результат неожидан, достаточно указать номер пункта и время сообщения — по ним можно найти ход в логах.

| № | Что попросить | Как узнать, что сработало |
|---|---|---|
| 1 | «Покажи строки 1–4 и 92–98 из `res://src/scripts/player.gd` одним запросом». | Одна карточка `read_file`, в параметрах `ranges:[[1,4],[92,98]]`; в ответе есть оба участка. После чтения в диалог не отправляется копия исходного запроса. |
| 2 | «Создай `res://src/scenes/agent_smoke.tscn` с корнем `Node2D` по имени `Smoke`, без скрипта». После подтверждения: «Добавь в корень этой сцены `Marker2D` по имени `Marker`». | На каждом шаге в предпросмотре одна сцена. У новой сцены в Godot дерево `Smoke → Marker`. Откат последнего шага убирает только `Marker`; откат первого — саму новую сцену. Скрипты в других сценах не мешают. |
| 3 | «В `res://src/refactor_lab/agent_test_material.tres` измени только `roughness` с `0.8` на `0.5` через `edit_resource`». | До подтверждения значение `0.8`. После — `0.5` в инспекторе материала; UID прежний. После отката — `0.8`. |
| 4 | «Через `edit_project_settings` добавь в Input Map только действие `agent_test` с deadzone `0.2`, без клавиш». | Один план для `res://project.godot`, без поиска описания инструмента в игровых скриптах. После подтверждения действие видно в **Project Settings → Input Map**; после отката оно исчезает. |
| 5 | «Перемести новый тестовый `.gd` с существующим `.uid` в другую папку». | В квитанции видны старый и новый пути скрипта и оба пути `.uid`. После отката скрипт и прежний UID снова на исходных местах. |

### Исходный материал для пункта 3

Если в новой копии тестового проекта нет `res://src/refactor_lab/agent_test_material.tres`, создайте его через `create_file` с таким содержимым:

```ini
[gd_resource type="StandardMaterial3D" format=3 uid="uid://crq2jm6gqr5a1"]

[resource]
resource_name = "Agent Test Material"
roughness = 0.8
```

## Дополнительные проверки

- **Сценовый линтер** `check(path, content)` доступен через `tools/probe.py` или MCP. Передайте текст `.tscn`, в котором после корня ребёнок `Child` с `parent="Branch"` объявлен раньше `Branch`. В ответе `changed: true`, а в `fixed` родитель стоит перед ребёнком. Сам файл не меняется.
- **Мелкая коррекция кода:** в тестовом `create_file` передайте `var\u00a0score = 1` (в JSON `\u00a0` означает неразрывный пробел). В предпросмотре между `var` и `score` должен быть обычный пробел. Это можно проверить без применения.
- **Диагностика GDScript:** отдельный инструмент `gd_lint(path)` на файле с `func demo()` без `:` возвращает `missing_colon` и номер строки; запись или автоматическое исправление синтаксиса не предполагается. Как и `check`, это самостоятельный инструмент, а не имя действия Qwen-чата.
- **Граница поддержки сцен:** работа с чистой тестовой сценой должна удаваться рядом с игровой сценой со скриптом. Если скрипт подключён к **самой цели или её зависимости**, безопасный отказ до записи ожидаем.
