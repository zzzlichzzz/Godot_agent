## Проверка исправления

Команды запускаются из корня аддона. Помимо зависимостей из [инструкции по установке](../README.md) для тестов нужен `pytest`; для живых проверок — соответствующая среда (редактор Godot, EXE или Chrome с совместимым ChromeDriver). Например, для изменения в обработке чата:

```powershell
python -m pip install pytest
python tools/selfcheck.py assistant.write
```

`selfcheck` проверяет слои, размеры, контракт, безопасность, тесты и корпус выбранного модуля. Для диагностики отдельной причины: `python tools/lint_arch.py`, `python tools/check_limits.py`, `python tools/gen_contract.py --check`, `python tools/security_audit.py`. Воспроизведение одного вызова: `python tools/probe.py <tool> --project <project> --args-file <args.json>`.

Проверяйте тот путь, на котором был баг: для маршрута панели — `tests/py/panel_tf/`, для редактора и браузера — `tests/py/live/`. Локальная страница в настоящем Chrome проверяет разбор ответа; она не доказывает доступность сайта провайдера. Для записи проверяйте байты до согласия, после применения и после отката на временном проекте.

При изменении сервера соберите кандидат командой `python tools/build_http_exe.py --candidate --work <новый-внешний-каталог>`. Для `tests/py/live/test_installed_server_start.py` задайте `GODOT_AGENT_TEST_SERVER_EXE` (кандидат) и `GODOT_AGENT_GODOT_BIN` (редактор); запуску нужен свободный порт 5000. Переносите проверенный EXE в `python/dist/` только после проверки, сравните SHA256 и запустите установленный файл.

## Если нужен старый материал

[Карта старых тестов](tests-map.md) сохранена без удаления строк: это учёт покрытия, а не очередь задач. Планы, листы механик, прежние ADR и подробные журналы доступны в [снимке перед очисткой](https://github.com/zzzlichzzz/Godot_agent/tree/e0e0758bd58da147c0f8eca818fde26f3514fcca/docs). Почему повседневная работа больше не требует листа переноса — [ADR-0101](adr/0101-maintenance-documentation.md).
