# ADR-0096: один запрос к браузерной модели вместо отдельного приветствия

- Статус: принято для поддерживаемого HTTP-шлюза (D121, 2026-11-26).
- Уточняет D117/D119 и [ADR-0093](0093-http-chat-prompt-and-ui-policy.md).

В D120 браузер сначала отправляет инструкцию агента и ждёт ответ, а потом
отправляет пользовательский текст. Пользователь видит лишний ход; он же
тратит время и токены. Отдельного системного поля на веб-странице нет.

- Шлюз объединяет инструкцию и пользовательский запрос в одном сообщении.
  Это не скрытое системное сообщение: инструкция видна в истории сайта.
  Если в этой сессии для того же чата, URL и версии инструкции уже получен
  корректный ответ, инструкция не дублируется. При обновлении контекста она
  снова идёт вместе с запросом, а не отдельным сообщением.
- Путь активной сцены — подсказка; её `.tscn` не загружается в начальный
  промпт. Для задачи по сцене модель может запросить ограниченную структуру
  через `list_scene` или нужные строки через `read_file`. Не прикладывать
  исходник автоматически и не читать сцены для обычного разговора.
- API сохраняет отдельное системное поле. Проверки вкладки, вложений,
  неоднозначной доставки, рубеж подтверждения записи и native-пины остаются.
  Чтение по запросу инструмента может потребовать ещё одного модельного хода;
  это не дублирование приветствия.
