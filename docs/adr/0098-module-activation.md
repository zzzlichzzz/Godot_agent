# ADR-0098. Контракт активации модулей

Принято, D130, 2026-11-27. Уточняет ADR-0003/0004, R-03 и R-05.

Чтобы добавить реализацию внутреннего порта, модуль объявляет `port_factories` в `ModuleSpec`. Ключ — имя порта, значение — фабрика от файлового адаптера профиля. Платформенные порты остаются в композиционном корне. Для зависимости от конкретного поставщика нужны `requires` (модуль) и `requires_ports` (порт). Одна и та же фабрика может обслуживать нескольких владельцев; разные фабрики одного имени не подменяют друг друга. Фабрики не должны открывать фоновые ресурсы: общего протокола закрытия этих ресурсов пока нет.

Гарантия загрузчика — изоляция **при сборке профиля**. Сначала он резервирует публичные имена, проверяет совместимость, отключения и граф зависимостей, затем создаёт порты, связывает вклады и публикует обработчики. `editing.rollback` получает отдельный вызов `recover` после активации. Он может восстановить старый журнал без `write_apply`; обратная зависимость запрещает новые записи без модуля отката.

Общие `setup/health/teardown`, горячая перезагрузка, отмена и таймауты произвольных обработчиков — отложенное расширение. Сегодня у них нет потребителя с согласованным временем жизни ресурсов и обратным порядком освобождения. Локальные точки входа отдельных механик и HTTP `/health` не являются этим протоколом.

Проверка: `tests/py/integration/test_module_composition.py` запускает новый интерпретатор без папки поставщика и со сломанным импортом второго. Вызов независимого инструмента, каскадный отказ, конфликты имён, старые адреса вкладов и раздельные контексты проверяются через собранного агента.
