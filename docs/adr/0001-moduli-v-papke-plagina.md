# ADR 0001. Модульная структура внутри папки плагина

- Статус: принято
- Дата: 2026-10-27
- Правила: R-01, R-02, R-03, R-05, R-11

## Контекст

Старый агент — 381 файл, ~10 МБ, 265 Python-файлов. Ядро «всё умеет» и
разъезжается в четыре ветки (MCP, HTTP/API, браузер, панель редактора). Крупные
файлы: `main.py` 304 КБ, `agent_start_screen.gd` 204 КБ, `parser_base.py` 198 КБ,
`agent_bridge.py` 142 КБ, панель разбита на `agent_panel_part1..5.gd` (~265 КБ).
Добавление возможности трогает несколько больших файлов, удаление — почти
невозможно.

Одновременно есть жёсткое требование: **весь код агента живёт внутри
`addons/godot_agent/`**, наружу ничего не выносится.

## Решение

1. Проект — монорепо внутри папки плагина: `editor/` (GDScript) + `python/`
   (Python) + `contract/`, `tests/`, `tools/`, `docs/`.
2. Внутри `python/` — три уровня переиспользования: `kernel/` (стабильные
   примитивы) → `modules/<область>/shared/` (общее внутри области) →
   `modules/<область>/<фича>/` (одна возможность).
3. Модульность применяется только к изменчивому слою. `kernel`, `protocol`,
   `channels`, `substrate` стабильны и статичны: это не модули, а каркас.
4. Модуль = папка. Подключение и удаление — только файловой системой
   (сканирование `modules/*/*/module.py`).
5. `id` модуля — `область.фича` (`editing.write_apply`), он же префикс
   capability. Имена инструментов остаются плоскими (`write_apply`), потому что
   это часть внешнего контракта.

## Следствия

Хорошо:

- новая возможность = новая папка, каркас не меняется;
- удаление фичи не ломает проект;
- область можно развивать, не читая остальные;
- границы проверяемы линтером (импорты, размеры файлов).

Плохо (принимаем):

- нужен загрузчик модулей (~300 строк критичного кода с тестами) и линтер
  границ (~50 строк правил);
- появляется динамический импорт, а значит требования к отсутствию побочных
  эффектов при импорте;
- 44 папки вместо 40 файлов: навигация по дереву становится важнее поиска.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Плоский `python/tools/*.py` как сейчас | Уже привёл к файлам по 100–300 КБ |
| Технические слои (`models/`, `services/`, `handlers/`) | Фича размазана по трём папкам, «найти и починить» трудно |
| Пакет вне плагина (`../godot_agent_agent`) | Нарушает R-01: код обязан быть в папке плагина |
| Один общий `shared/` на весь проект | Превращается в свалку и в неявные связи между областями |
