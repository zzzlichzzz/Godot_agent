# ADR-0092 — безопасная архивация мёртвого http_endpoint.json на старте сервера

2026-11-25. Повторный инцидент блокировки старта `godot_agent_server.exe` при рестарте Godot.

## Контекст и проблема

После удаления эвристики `unlink()` в ADR-0090 (`SEC-T1-LOCAL-04`) редактор при обычном закрытии или краше не всегда отправляет `/server/shutdown` до завершения процесса. В `%APPDATA%\Godot\app_userdata\<проект>` остаётся `http_endpoint.json` от уже завершённого процесса (подтверждено трижды: `PID 18332`, `PID 26668`, `PID 29240`). На следующем запуске `listener.py` открывает `http_endpoint.json` в режиме `'x'` и немедленно падает с `FileExistsError` → код возврата `2`.

## Решение до кода

Уточнить политику `listener.py` так, чтобы **никогда не удалять и не усыновлять** живые, чужие или неполные записи, но при этом не блокировать повторный старт после аварийного завершения предыдущего собственного сервера:

1. После успешного биндинга нового loopback-сокета (`make_server('127.0.0.1', port, ...)`), если `endpoint.open('x')` вернул `FileExistsError`, `listener.py` проверяет существующий файл `http_endpoint.json`:
   - Обычный файл (не symlink, не reparse point/junction, `st_nlink == 1`, размер `<= 4096` байт).
   - Валидный JSON-объект со всеми четырьмя полями записи слушателя: `host == '127.0.0.1'`, целочисленный `port` (`1024..65535`), целочисленный `pid > 0` (`pid != os.getpid()`, не `bool`), непустой строковый `session_id` (без лишних полей).
   - ОС подтверждает, что процесс `pid` **гарантированно не существует** (на Windows: `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` вернул `0` с `GetLastError() == 87` (`ERROR_INVALID_PARAMETER`), либо хендл завершён с кодом выхода `!= 259`; при `ERROR_ACCESS_DENIED` процесс считается живым fail-closed).
2. Только при выполнении всех условий выше старый файл **не удаляется молча**, а атомарно архивируется рядом (`http_endpoint.stale-<pid>-<timestamp>.json` через эксклюзивное создание с сохранением точных сырых байтов), после чего повторно выполняется `endpoint.open('x')` для нового сервера.
3. Все прежние отказы сохраняются неизменными: битый JSON (`not-json`), `pid=0`, отсутствие `host`/`port`/`pid`/`session_id`, живой `pid`, `ERROR_ACCESS_DENIED`, symlink/hardlink — по-прежнему завершаются `FileExistsError` без изменения файла.
4. Все прежние тесты `test_endpoint_owner.py` и `test_http_metadata_policy.py` сохраняются без ослабления.
