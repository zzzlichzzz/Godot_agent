# ADR-0100 — Файлы проекта через Godot

Уточнение D135 для запуска сервера из Проводника: EXE без аргументов может повторно использовать редактор, который уже прочитал конфигурацию этого проекта через `FileAccess`. Привязка хранится в `%LOCALAPPDATA%/GodotAgent/launchers`, отдельно для каждого корня проекта, с проверкой идентичности файла. Явно заданный движок приоритетнее. При первом интерактивном запуске путь может указать сам пользователь. Метаданные проекта не служат источником команды запуска.

Рабочие байты и перечисление файлов для инструментов получает отдельный Godot той же установки, что и редактор. Он запускает только поставляемый примитив FileAccess/DirAccess в пустом проекте: autoload и плагины исследуемой игры не запускаются. Связь по закрытым stdin/stdout; команды и путь программы не берутся из ответа модели. Вне редактора движок указывается через `GODOT_AGENT_GODOT_BIN` или находится в PATH. Нет движка — нет подмены чтением с диска.

Политика путей, физическая идентичность файлов/каталогов, журнал, эксклюзивная публикация, fsync и резервные копии остаются ответственностью сервера. Данные для записи сначала сохраняет FileAccess, затем WAL публикует их атомарно. Старые анализаторы с файловым интерфейсом могут работать на ограниченном временном снимке, полученном через Godot; снимок не является рабочим проектом. Дисковый адаптер остаётся тестовым двойником.

Перед обоими предпросмотрами переименования сохраняется прежняя проверка закрытого подкласса: `PathPolicy.protected_override_candidate` допускает только внутреннее сравнение сигнатуры. Через эту проверку нельзя получить исходник, имя файла или правку. При совпадении либо невозможности проверки план не выдаётся. Закрытый файл не включается в снимок анализатора, отчёт, журнал или запрос модели.
