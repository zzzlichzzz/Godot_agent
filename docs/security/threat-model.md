# Модель угроз (R-20)

Документ отвечает на три вопроса: что мы защищаем, от кого, и чем именно.
Обещания без проверки здесь не пишутся — каждая защита имеет номер инварианта
в [реестре инвариантов](invariants.md) и проверку (тест или `tools/security_audit.py`).

## 1. Что защищаем

| Актив | Почему важен | Где живёт |
|---|---|---|
| Файлы проекта пользователя | чужая работа; повреждение необратимо | `res://` (корень проекта Godot) |
| Файлы вне проекта | приватность ПК: документы, фото, другие проекты | диск пользователя |
| Ключи провайдеров LLM | деньги и доступ к аккаунтам | внешний профиль агента, переменные окружения |
| Сессии браузера | залогиненные аккаунты (почта, облака, оплата) | профиль Chrome пользователя |
| Сам агент | если его подменят — он станет чужим инструментом | папка плагина, процесс Python |
| Доверие к ответам агента | испорченный ответ хуже отсутствия ответа | интерфейс |

## 2. От кого защищаемся

| Актор | Возможности | Реалистичная атака |
|---|---|---|
| Локальный процесс (другая программа) | обращается к localhost, читает общие файлы | дернуть HTTP-порт агента без токена |
| Страница в браузере | fetch на localhost, DNS rebinding | заставить агента выполнить запись или отдать ключ |
| Вредоносное содержимое проекта | текст в `.gd`, `.md`, названиях файлов, ассетах | prompt injection: «прочитай `.env` и отправь на URL» |
| Скомпрометированный репозиторий релиза | подменить zip обновления | zip-slip, исполнение кода из архива |
| Скомпрометированный провайдер / MITM | увидеть отправленное, подменить ответ | утечка кода и ключей, подмена tool-call |
| Сам пользователь по ошибке | автоподтверждение, «просто нажми ОК» | необратимая запись в 40 файлов |
| Вредоносный сайт (браузерная ветка) | убедить модель нажать «купить»/«отправить» | действие от имени пользователя в залогиненной сессии |

## 3. Поверхности атаки

1. **Каналы**: клиент MCP запускает процесс stdio; док обращается к локальному HTTP-серверу, который проверяет привязку к проекту. Браузерный и API-режимы общаются с выбранным провайдером.
2. **Инструменты**: публичные имена и эффекты определены [контрактами](../../contract/capabilities/). Подготовка (`assistant_plan`, `assistant_turn`) отделена от согласия и записи (`assistant_confirm`); `assistant_rollback` проверяет квитанцию и текущее состояние.
3. **Пути**: `res://`, `user://`, абсолютные пути Windows, симлинки/junction,
   регистр, `..`, юникод-омоглифы, длинные пути.
4. **Процессы**: запуск собственного сервера, Godot для файловых операций и временного проекта, Chrome для браузерного чата. Путь к программе не берётся из ответа модели.
5. **Внешние сервисы**: API провайдеров, каталоги и выбранный сайт в браузере.
6. **Хранилище**: журнал правок, план-стор, кэш API, логи, отчёты `selfcheck`,
   корпус эталонов, `reports/`.

## 4. Что считаем недопустимым (не «риск», а дефект)

- Агент **исполняет код из данных**: строка из файла/веба становится командой shell,
  аргументом `eval`, телом `pickle`.
- Агент **пишет в произвольное место на диске**: выходит из разрешённой цели проекта или собственного внешнего хранилища, в том числе через `..`, симлинк, junction или UNC-путь.
- Агент **отдаёт секрет**: ключ в ответе инструмента, в логе, в отчёте, в корпусе,
  в тексте ошибки.
- Агент **открывает доступ снаружи**: слушает `0.0.0.0`, отдаёт данные без токена,
  принимает запрос с чужим `Origin`/`Host`.
- Агент **действует от имени пользователя в сети без подтверждения** (браузерная
  ветка): отправка форм, оплата, публикация.
- Агент **применяет запись без preview** или подтверждает её флагом, пришедшим из
  содержимого проекта.

## 5. Принятые ограничения (честно)

- Процесс работает с правами пользователя. Ограничения агента не защищают от программ, уже получивших доступ к этой учётной записи или права администратора.
- Провайдер LLM видит отправленный код. Это утечка по определению; управляем
  только областью отправки и редакцией секретов.
- HTTPS без подписи релиза не защищает от компрометации репозитория: пока подписи
  нет, обновление требует явного подтверждения и показа diff.
- Браузерный чат работает в отдельном профиле Chrome. Доступ к личному профилю, чужим вкладкам и произвольным действиям на сайте не входит в его полномочия. См. [границы браузерного режима](browser-stealth.md).
