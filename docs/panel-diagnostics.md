# Диагностика панели

## Сервер не запускается

1. Проверьте, что рядом с `res://addons/godot_agent/plugin.cfg` есть `python/dist/godot_agent_server.exe`. В копии из Git его нужно [собрать](../README.md#установка-из-исходников-на-windows).
2. Запустите из панели: она передаёт путь к **этому** редактору даже без Godot в `PATH`. При прямом запуске EXE без аргументов важны путь установки и сохранённая привязка к проекту. Если редактор переместили, снова запустите сервер из панели.
3. В **Проект → Открыть папку пользовательских данных** (`user://`) найдите `http_endpoint.json`. [Запрос `/init`](clients.md#http-уже-запущенного-дока) должен вернуть корень текущей игры. Если порт 5000 занят другим проектом, сначала штатно остановите его сервер. Не удаляйте токен у работающего процесса.

## Ответ завис или результат не совпал с сообщением модели

В `user://agent_chats.json` хранится диалог. Для записи отдельно проверьте предпросмотр, квитанцию и состояние файла: сообщение модели не подтверждает применение. В `user://agent_turn_timings.json` хранятся времена **последних 64 ходов**, включая продолжения после разрешённого чтения. Если задержка повторилась, запишите примерное время и что показала панель.

| Поле | Что оно показывает |
|---|---|
| `utc_s` | Начало хода, Unix-время UTC в секундах |
| `first_text_ms`, `visible_done_ms` | Когда сервер впервые увидел текст и конечную строку `===DONE===` в потоке |
| `verify_ms`, `total_ms` | Когда началась проверка и когда диспетчер получил итог. Все времена в миллисекундах от начала хода |
| `kind`, `outcome`, `chars` | Тип запроса (например, продолжение чтения или отчёт о переименовании), исход хода, наибольшее число символов по данным наблюдателя |
| `read_tool`, `read_results` | Только для выполненного запроса чтения: инструмент и упорядоченные метки (`empty` — пустая страница, `truncated` — есть продолжение, `directory` — передан каталог, `missing_names` — есть ненайденные имена) |

Для ответа с замеченным маркером `total_ms − visible_done_ms` показывает время от наблюдения маркера до завершения диспетчера. Отрисовка Godot и момент, когда пользователь увидел ответ на сайте, сюда не входят. `null` означает «не наблюдалось»: у API нет этих браузерных событий, а окно наблюдения потока ограничено. Это не доказательство, что модель пропустила маркер.

Журнал хранится локально, отдельно от сохранённых чатов. Тексты, содержимое файлов, их пути, адреса, идентификаторы чатов, ключи и аргументы действий в него не попадают.

При разборе `ask_librarian` смотри `read_tool: "ask"`. До D127 успешный текстовый ответ мог получить метку `error`; для такого старого хода сверь результат с сохранённым диалогом. Начиная с D127 непустой текст отмечается `ok`, пустой — `empty`. Старые записи не переписываются.
