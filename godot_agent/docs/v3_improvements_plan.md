## Часть 1. Архитектура агента (карта + гейт)

Вопросы → ответы владельца:

1. Карта `docs/ARCHITECTURE.md` + машинная карта `docs/architecture_map.json`. —
   Согласен; главное записать правило: функции практически все написаны в
   ядре; агенты (браузер, редактор, API, MCP) обращаются к ядру и используют
   его функцию в своей сфере, при необходимости чуть модифицируя; единая
   точка входа функционала; браузер — минимум итераций, API — обычный
   стандарт агентов. → **ВЫПОЛНЕНО**.
2. Гейт в мосте не «сторож-агент», а данные + проверка при записи. —
   Согласен, «надеюсь исправление не будет очень сложным». → **ВЫПОЛНЕНО**
   (гейт в `agent_bridge`, exe не пересобирается — мост живёт вне сборки).
3. Детектор дублей имён (ядро ↔ потребители). — Да. → **ВЫПОЛНЕНО**
   (`arch_map.audit` + `tools/arch_audit.py`: гейт ловит НОВЫЕ файлы,
   аудит — периодический отчёт по всему дереву).
4. Разовый аудит существующих мест, где функциональность живёт не через
   ядро. — Согласен; «не страшно, запускать при появлении новых файлов». →
   **ВЫПОЛНЕНО**: гейт срабатывает на каждой новой записи (agent-dev);
   первый аудит нашёл 3 реальных дубля (ниже) — решение по каждому за
   владельцем.
5. Проверка имён «серых» зон отключена (`check_names: false` для тестов,
   n8n, per-site парсеров) — чтобы гейт не шумел на легитимных фикстурах. —
   Ок.

Найденные дубли (инвентарь 13.10.2026, `python -B tools/arch_audit.py`):

- `format_report` — ядро `runtime_checks.py` ↔ `server/log_reader.py`;
- `format_snapshot`, `normalize_snapshot` — ядро `runtime_debug.py` ↔
  `server/editor_context.py`;
- 14 совпадений имён рабочих скриптов/протоколов (селениум-колбэки
  `capture*`, `complete_chat`/`stream_chat` anthropic/openai_compat,
  `forget`/`get` catalog/model_cache) — вероятная норма для per-site
  скриптов; гейт их не трогает.

Долги гейта v1 (осознанно отложены):

- `move_file` (переименование файлов) пока не гейтится — только create/patch;
- `.gd`-файлы — предупреждение зоны, без сверки имён;
- панельный путь (`main.py`/exe) гейт не видит — только мост :8000.

## Часть 2. Схема v3 (доп. улучшения)

1. **Итерации агентов.** Владелец: «починить первопричину, а не убирать
   количество итераций; виноват был мой инструмент; 6М токенов на задачу —
   не много». → Первопричина исправлена в 0.8.6 (MCP :8000 режет входные
   аргументы и ответы; лимит поисковиков 50 сохранён). Лимиты не трогаем.
2. **Токен-сводка в отчёте цикла.** Владелец: «для контроля — хорошо, чтобы
   понимать траты и чинить при случае». → В работе: сводка в цикл-отчёт
   (стадия 4/финал) с разбивкой по агентам; fallback — `token_report.py`.
3. **Baseline тестов (дельта до/после).** Владелец: «если улучшит
   выполнение, не съест больше токенов/времени и даст результат без багов —
   можно». → В работе, экономно: один прогон эталонных тестов до фикса,
   дельта после.
4. **События прогресса.** Владелец: текущий режим (молчание до ~10 мин)
   устраивает; важно, что цикл стартует после сообщения. → Не делаем.
5. **EN для стадий 1–2.** Владелец: «полезно — нейросети начнут думать на
   английском, меньше токенов». → В работе: промпты chainLlm «X: 1. Причина»
   и «X: 2. Синтетические тесты» — на английском.
6. **Сжатие памяти при перезапуске круга.** Владелец: «при новом круге
   сжимать историю до нужного для продолжения: где пробовали, что не
   сработало/сработало — чтобы повторный цикл имел КПД выше». → В работе.
7. **Новые каналы.** Владелец: «4 канала покрывают почти всё; новых не
   планируем». → Не делаем.
