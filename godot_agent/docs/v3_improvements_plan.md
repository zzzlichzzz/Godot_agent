Найденные дубли (инвентарь 13.10.2026, `python -B tools/arch_audit.py`):

- `format_report` — ядро `runtime_checks.py` ↔ `server/log_reader.py`;
- `format_snapshot`, `normalize_snapshot` — ядро `runtime_debug.py` ↔
  `server/editor_context.py`.

Разбор 13.10.2026 (вопрос владельца: «слить или оставить исключением?»):
это **не дубли, а одноимённые функции разных доменов** — `runtime_checks`
форматирует JSON-отчёт проверки запуска (EN-обёртка для модели), а
`log_reader` собирает RU-отчёт по логу запущенной игры с группировкой по
файлам; `runtime_debug` описывает снимок запущенной игры (protocol+секции),
`editor_context` — снимок редактора (schema-v1: сцена/выделение/скрипт).
Слияние дало бы функцию с двумя схемами и риском сломать формат промптов
панели при нулевой выгоде. Решение: **не сливать, а развести явными
именами** у потребителей — `log_reader.format_log_report`,
`editor_context.normalize_editor_snapshot` / `format_editor_snapshot`
(ядро не тронуто, поведение не менялось; тесты обновлены в том же коммите).
После этого аудит по дублям «ядро ↔ потребители» чист: 0.
- 14 совпадений имён рабочих скриптов/протоколов (селениум-колбэки
  `capture*`/`on_*`, `complete_chat`/`stream_chat` anthropic/openai_compat,
  `forget`/`get` catalog/model_cache) — норма для per-site скриптов; гейт

Долги гейта v1 (осознанно отложены):

## Часть 2. Схема v3 (доп. улучшения)

1. **Итерации агентов.** Владелец: «починить первопричину, а не убирать
   количество итераций; виноват был мой инструмент; 6М токенов на задачу —
   не много». → Первопричина исправлена в 0.8.6 (MCP :8000 режет входные
   аргументы и ответы; лимит поисковиков 50 сохранён). Лимиты не трогаем.
2. **Токен-сводка в отчёте цикла.** Владелец: «для контроля — хорошо, чтобы
   понимать траты и чинить при случае». → **ВЫПОЛНЕНО** (13.10.2026). Живая
   сводка внутри воркфлоу невозможна (usage моделей-суб-нод попадает в базу
   только после завершения исполнения; каналы — отдельные исполнения), поэтому
   сводка пост-прогонная: по событию `kind=done` сервер рук (:8010) запускает
   `n8n/scripts/postrun_tokens.py` — скрипт ждёт завершения ядра, добирает
   исполнения волны (ядро + каналы), переиспользует `token_report.py` и
   печатает `TOKENS_JSON`; рука пишет в журнал «цикл → чат» событие
   `kind=tokens` (вызовы, est prompt/completion, топ-5 моделей). Живой тест:
   прогон 103 — 127 вызовов, est prompt ~3,88 М + completion ~256 К.
   Активация хука — после перезапуска сервера рук; выключатель —
   `N8N_HANDS_NO_TOKEN_HOOK=1`; fallback остаётся — `token_report.py` вручную.
3. **Baseline тестов (дельта до/после).** Владелец: «если улучшит
   выполнение, не съест больше токенов/времени и даст результат без багов —
   можно». → **ВЫПОЛНЕНО** (13.10.2026), экономно: у всех четырёх каналов
   стадия «3. Фикс» перед правкой прогоняет синтетический тест шага 2
   (baseline: тест обязан упасть; зелёный baseline запрещает правку —
   applied=NO), стадия «4. Прогон тестов» подтверждает после фикса; парсеры
   шагов несут `baseline`/`delta` («было FAILED до фикса -> GREEN после
   (подтверждено)» / «GREEN до и после (тест не воспроизводил баг)» /
   «после фикса RED (дельта не подтверждена)»). «MCP: руки» подключены к
   «X: 3. Фикс» (4 связи ai_tool). Цена: один `run_command` на прогон правки.
4. **События прогресса.** Владелец: текущий режим (молчание до ~10 мин)
   устраивает; важно, что цикл стартует после сообщения. → Не делаем.
5. **EN для стадий 1–2.** Владелец: «полезно — нейросети начнут думать на
   английском, меньше токенов». → **ВЫПОЛНЕНО** (13.10.2026): промпты 8 цепочек
   «X: 1. Причина» и «X: 2. Синтетические тесты» переведены на английский
   (ключи ответов `nothing_to_do`/`hypothesis`/`test`/`test_path` без
   изменений); снимок синхронизирован (versionId `acc810ed`), сверка
   «Совпадает», секретов 0.
6. **Сжатие памяти при перезапуске круга.** Владелец: «при новом круге
   сжимать историю до нужного для продолжения: где пробовали, что не
   сработало/сработало — чтобы повторный цикл имел КПД выше». →
   **ВЫПОЛНЕНО** (13.10.2026): «Сборщик информации (4 канала)» обязан
   завершать свод блоком «[ИТОГ КРУГА]» — пробовали / сработало / не
   сработало / осталось (≤700 символов, только факты текущего запуска,
   архив прошлых запусков в блок не переносится). Блок уходит Аудитору
   (через «Счётчик кругов»), в память `collector-*` и оттуда — в контекст
   следующего круга вместо сырой истории.
7. **Новые каналы.** Владелец: «4 канала покрывают почти всё; новых не
   планируем». → Не делаем.
