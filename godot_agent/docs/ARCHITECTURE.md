# Архитектура Godot Agent — правила и карта

Короткое правило: **функциональность живёт в ядре; все оболочки вызывают ядро.**
Панель, сервер, браузер, API-слой, бэкенды и MCP-мост — потребители: они
добавляют только тонкую проводку в своей сфере и не копируют логику ядра.

Машиночитаемая версия правил — `docs/architecture_map.json`; её читает гейт
моста (см. «Гейт» ниже). Этот документ объясняет «почему».

## Слои

### Ядро — `python/godot_tools/`
Единственная точка входа функциональности агента. Здесь живут: рефакторинги
(`symbol_refactor`, `file_refactor`, `node_refactor`), чтение и контекст
(`gather_context`, `librarian`, `gd_semantic_parser`, `gd_functions`), проверки
(`gd_lint`, `gd_api_check`, `tscn_lint`, `godot_headless_validation`), действия
(`scene_actions`, `resource_actions`, `project_settings_actions`,
`transaction_actions`, `high_level_actions`), служебное (`history_manager`,
`project_tools`, `answer_judge`, `runtime_checks`, `runtime_debug`, `scene_deps`,
`gd_api_cache`).

Правило: **новая функция агента появляется здесь** — вместе с тестом
(`python/tests/`). Потребитель, которому чего-то не хватает, расширяет ядро,
а не заводит свою копию.

### Потребители (оболочки)

| Слой | Где | Роль |
|---|---|---|
| Панель/редактор | `agent_*.gd`, `main.py` (сервер панели, :5000) | UI и оркестрация; действия исполняются функциями ядра |
| Браузер | `python/browser/`, `backends/browser_backend.py` | водит Chrome по сайтам; «минимум итераций» — простые вызовы |
| API-слой | `python/api/`, `backends/api_backend.py` | провайдеры, ключи, каталог моделей |
| Парсеры ответов | `python/parsers/` | разбор ответов сайтов; общая логика — в `parser_base` |
| Мосты | `python/tools/agent_bridge.py`, `godot_agent_mcp.py` | CLI/MCP-доступ к ядру; единственный источник истины по доступу и записи |
| n8n-фабрика | `n8n/` (вне процесса агента) | каналы вызывают мосты: :8000 (запись) и руки :8010 |

Потребитель может незначительно адаптировать функцию ядра под свою сферу, но
**не переписывает её копию**: при нестыковке расширяется ядро.

### Потоки

- Панель → сервер (`main.py`, :5000) → ядро → файлы проекта.
- Внешние агенты (n8n, Cline) → MCP :8000 (`tools/godot_agent_mcp.py`, профили
  `user`/`agent-dev`) → `agent_bridge.py` → ядро. Запись двухфазная:
  `write preview` → `plan_id` → `write apply`.
- «Руки» (:8010) — отдельный сервер инструментов среды; в аддон не входит.

## Правила новых файлов и функций

1. Функциональность — в ядро; оболочка — тонкая проводка в своей сфере.
2. Имя новой публичной функции (.py) не должно повторять имя функции ядра
   (исключения — `name_stoplist` в карте).
3. Новый файл должен попадать в описанную зону карты; зоны с `deny` —
   генерируемые каталоги (`dist`, `__pycache__`, `agent_api_cache`, ...).
4. Новая функциональность — с тестом; тесты живут в `python/tests/`.
5. Чистота: один файл — не свалка. Лимит размера задан в карте (`limits`,
   1500/2000 строк для `.py`/`.gd`): новый файл сверх лимита гейт отклоняет
   («раздели функциональность на модули ядра»), близкий к лимиту — строка
   `arch:`. Накопленные крупные файлы показывает `arch_audit`; разбивка —
   при следующей правке по такому файлу.
6. Файл лежит в своей зоне карты: `*.py` в корне аддона и зона вне карты —
   предупреждение, `deny` — отказ. Перенос файла («не на своём месте») —
   задача `move_file`, гейт переезд не блокирует.
7. Новая зона или исключение — осознанное решение: правка карты в том же
   коммите.

## Гейт (автоматическая проверка)

Мост (`agent_bridge.py`, режим `agent-dev`) при создании НОВЫХ файлов агента:

- читает `docs/architecture_map.json` и определяет зону каждого нового файла;
- имя из ядра → **отказ** с указанием, где функция уже определена;
- зона-потребитель (`warn`) → предупреждение `arch:` в ответе preview/apply;
- зона `deny` → отказ; зона вне карты → предупреждение;
- размер нового `.py`/`.gd`: больше `limits.line_max` строк → отказ, от
  `limits.line_warn` строк → предупреждение (роли из `line_exempt_roles` —
  скрипты n8n, generated, tasks, reports — не считаются);
- зоны с `check_names: false` (тесты, скрипты n8n, per-site парсеры)
  сверяются только по зоне: одноимённые фикстуры там — норма, а не дубль;
- строки `arch:` в ответе моста — сигнал для стадии-архитектора n8n.

Проверка работает только в `agent-dev` и только для файлов внутри аддона:
пользовательские проекты (`user`/`project`) карта не касается.

Периодическая проверка: `python -B tools/arch_audit.py` — отчёт по дублям имён
(ядро ↔ потребители, потребитель ↔ потребитель), файлам вне зон карты (не на
своём месте) и крупным файлам (секция «крупные файлы»; свыше `line_max` —
«раздели на модули»). Только чтение, ничего не меняет.

## Известные долги (v1 гейта)

- `move_file` в гейт не входит (перемещение не добавляет новой функции);
- `.gd`-файлы — только предупреждение зоны (без анализа имён);
- панельный путь записи (`main.py`) гейт пока не вызывает — следующий шаг,
  чтобы правило стало сквозным;
- карта описывает только этот аддон: внешние аддоны и проекты не затрагивает;
- крупные файлы, накопленные до введения лимитов (инвентарь — в отчёте
  аудита), гейт не трогает: он действует только на НОВЫЕ файлы. Разбивка —
  при следующей правке по каждому такому файлу.
