# Документы проекта — что где

<!-- INDEX -->
Указатель документации агента. Если не помнишь название файла — начинай отсюда.

| Документ | Зачем |
|---|---|
| `STATUS.md` | **состояние: что сделано, что не доделано, следующий шаг** (+ блок «передача в новый чат») |
| `ARCHITECTURE.md` | правила архитектуры: функциональность — в ядре, оболочки — тонкая проводка |
| `architecture_map.json` | машиночитаемая карта зон и лимитов; её исполняет гейт моста (`agent_bridge.py`, режим `agent-dev`) |
| `split_gd_transfer_map.md` | где искать тело метода после раскола панели (230 методов → 5 модулей) |
| `v3_improvements_plan.md` | план v3 и накопленные долги |
| `librarian_search_plan.md` | **починка поиска Библиотекаря** + «карточка символа» (функция со связями); полигон — реальный проект |
| `limitations/` | ограничения окружения (например: живой UI-прогон панели невозможен headless) |

Карта кода в одну строку: `../python/godot_tools/` — ядро (вся функциональность);
`../python/main.py` — сервер панели :5000; `../agent_*.gd` — панель редактора;
`../python/tools/` — мосты (CLI + MCP :8000); `../n8n/` — фабрика каналов.

Прогон тестов (из корня репозитория): `python -B godot_agent/python/tests/run_integration_regressions.py`

Не документация, а история (читать как историю, не как текущую правду):
`../ОТЛОЖЕНО.md`, `../GODOT_INTEGRATION_ROADMAP.md`, `../VISUAL_UI_ROADMAP.md`,
`../reports/`, `../tasks/`.
