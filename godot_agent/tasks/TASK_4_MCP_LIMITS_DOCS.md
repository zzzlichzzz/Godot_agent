## 1. Проблема

Документация обещает больше, чем есть.

**README** (`README.md`, раздел «Экспериментальное») говорит про MCP:

> Тот же кэш ClassDB вашей версии движка, Библиотекарь, поиск по проекту, движок переименований и проверка кандидата настоящим Godot в headless — но уже как настоящие инструменты, а не как текстовая инструкция.

Формулировка создаёт впечатление равного набора возможностей. Это неверно: часть операций требует запущенного редактора и через MCP **недоступна в принципе**.

**Инструкция** (`python/tools/MCP_ALPHA.md`, строки 278-279) до сих пор утверждает:

> Это НЕ настоящий MCP-stdio-сервер, а CLI + инструкция

Это устарело: настоящий MCP-сервер существует (`python/tools/godot_agent_mcp.py`, точка входа `def main`). Точные номера строк сверяйте сами — файл растёт.

## 2. Что именно недоступно через MCP и почему

| Операция | Почему недоступна |
|---|---|
| `create_scene`, `edit_scene` | запись через `agent_scene_executor.gd` в редакторе |
| `edit_resource` | через `agent_resource_executor.gd` |
| `edit_project_settings` | через `agent_project_settings_executor.gd` |
| `inspect_runtime` | нужна запущенная игра с автозагрузкой `AgentRuntimeBridge` |
| `run_check` | отключён намеренно (`main.py:1280-1289`) |

Общее у всех: **мост работает без редактора**, а эти операции требуют `PackedScene` / `ResourceSaver` / `ProjectSettings` — то есть главного потока редактора Godot.

Это не дефект, а осознанное свойство: MCP-профиль задуман как работа **без** редактора.

## 3. Что сделать

### 3.1. README, раздел про MCP

Заменить формулировку, создающую ложное ожидание. Нужно ясно разделить:

- **что доступно через MCP** — чтение проекта, Библиотекарь, поиск, проверка линтерами, headless-валидация, запись файлов и переименования;
- **что недоступно** — всё, что требует редактора: структурные операции со сценами, ресурсами, настройками, runtime-инспекция.

### 3.2. `MCP_ALPHA.md`

1. Убрать утверждение, что настоящего MCP-сервера нет.
2. Добавить раздел «Чего не умеет» с таблицей из раздела 2 этого задания.
3. Убедиться, что инструкция по подключению ссылается на `godot_agent_mcp.py`, а не только на CLI `agent_bridge.py`.

### 3.3. Описания инструментов

Файл: `python/tools/godot_agent_mcp.py`.

Проверить описания инструментов (декораторы `@server.tool`). На момент аудита их **20 в профиле `agent-dev`** и **14 в `user`**: базовые десять, четыре команды чтения, три предпросмотра узлов и три фазы записи. Все они работают без редактора, поэтому ограничения касаются не их, а **отсутствующих** инструментов.

Задача здесь одна: если в описании какого-то инструмента есть намёк на работу со сценами или настройками — убрать.

### 3.4. Проверить утверждения фактами

**Это важно.** Не переписывайте по этому заданию — проверьте каждое утверждение запуском:


Если найдёте расхождение с этим заданием — **верьте коду, а не заданию**, и опишите расхождение в отчёте.

## 4. Как проверять

### 4.1. Документация не содержит ложных обещаний

Пройдите по README и `MCP_ALPHA.md` и для каждого утверждения про MCP ответьте: «это можно проверить запуском?». Если нет — формулировку надо смягчить или убрать.

### 4.2. Точность ссылок

Все упомянутые в документации файлы и функции должны существовать:

```powershell
cd 'D:\vajno\Godot\тест-плагина-ии\addons\Godot_agent'
Test-Path godot_agent\python\tools\godot_agent_mcp.py
Select-String -Path godot_agent\python\tools\godot_agent_mcp.py -Pattern 'def main'
```

### 4.3. Тесты не задеты

Задание только про текст, поэтому тесты обязаны остаться зелёными:

```powershell
cd 'D:\vajno\Godot\тест-плагина-ии\addons\Godot_agent\godot_agent\python'
cmd /c "python tests\test_gdscript_wiring.py > out.txt 2>&1"
Get-Content out.txt -Tail 1        # ожидается: ИТОГО: 109/109
Remove-Item out.txt
```

**Внимание:** `test_gdscript_wiring.py` проверяет локализацию в `.gd`, а не документацию, поэтому на README он не влияет. Тем не менее прогоните — убедиться, что ничего не задето случайно.

## 5. Критерии приёмки

1. В README ясно сказано, что доступно через MCP, а что нет.
2. В `MCP_ALPHA.md` нет утверждения об отсутствии MCP-сервера.
3. Есть таблица ограничений с объяснением **почему** (требуется редактор).
4. Все файлы и функции, упомянутые в документации, существуют.
5. `test_gdscript_wiring.py` — 109/109.
6. Ни одно утверждение в документации не обещает того, что нельзя проверить запуском.
