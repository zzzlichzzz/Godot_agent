# ЗАДАНИЕ 3: перехват переименования узлов

**Проект:** Godot Agent — плагин ИИ-ассистента для редактора Godot 4
**Корень:** `D:\vajno\Godot\тест-плагина-ии\addons\Godot_agent\godot_agent`
**Движок:** Godot 4.6.3-stable
**Объём:** 2-3 дня
**Зависимости:** не пересекается с заданиями 1 и 2 по файлам, но требует понимания их результата

---

## 1. Проблема

Плагин перехватывает переименование **файлов** и сам чинит ссылки. Переименование **узлов** не перехватывает вообще.

| Человек сделал в редакторе | Реакция плагина |
|---|---|
| переименовал файл в доке файлов | перехват есть, `preload` / `load` / `extends` / `ext_resource` обновляются сами |
| переименовал узел в дереве сцен | **ничего**, `$Node` в скрипте ломается молча |

Из-за этого человек получает порванную ссылку и решает, что сломан плагин. Узел приходится переименовывать через отдельный диалог меню — а это противоречит замыслу: функция должна работать нативно, как с файлами.

---

## 2. Что уже известно и проверено

**Сигнал существует.** Проверено на живом движке 4.6.3:

```
НАЙДЕН сигнал renamed
  args=[]        ← ноль аргументов
```

`Node.renamed` есть. Но **прежнее имя из него не узнать** — аргументов нет, и отдельного метода «дай прежнее имя» тоже нет (проверено, есть только `get_name` / `set_name`). Значит понадобится снимок имён.

**Заготовка уже стоит.** В `agent_integration_signals.gd` подписаны шесть сигналов `EditorPlugin`, среди них `scene_changed` (строка 53). Обработчик `_on_scene_changed` (строка 92) сейчас пустой — это и есть точка, откуда надо начинать.

**Перехват файлов работает так** — образец для подражания:

```
agent_entry.gd:_on_fs_files_moved
  → панель.handle_filesystem_move()
    → _fs_move_queue (очередь, чтобы не шлaть запросы шквалом)
      → _send_post_move_sync()
```

Обратите внимание на очередь: Godot шлёт `files_moved` на каждый файл пакета при drag-and-drop. Для узлов такой проблемы нет, но структуру стоит повторить.

## 3. Требуемое поведение

**Применять сразу, без вопроса — как для файлов.** Это согласованное решение: смысл задачи в том, чтобы узел вёл себя как файл, а не порождал ещё один диалог.

Плюс обязательное **уведомление в панели**: человек должен видеть, что ссылки обновлены. Молчаливая правка чужого кода недопустима, даже если она правильная.

Если по ходу работы окажется, что молчаливое применение опасно — **остановитесь и опишите проблему в отчёте**, не заменяйте решение самовольно на подтверждение.

## 4. Что сделать

### 4.1. Подписка и снимок имён

Файл: `agent_integration_signals.gd`.

1. В `_on_scene_changed(root: Node)` обойти дерево открытой сцены и подписаться на `renamed` каждого узла.
2. Держать карту `{instance_id: last_known_name}` — без неё прежнее имя не восстановить.
3. При сигнале: взять прежнее имя из карты, сравнить с текущим, обновить карту.
4. Отписываться от узлов, которые покидают сцену, иначе карта растёт и держит ссылки на удалённые объекты.

**Проверка снимка:** переименуйте узел дважды подряд — оба раза прежнее имя должно определиться верно.

### 4.2. Подавление собственных переименований

Когда узел переименовывает сам плагин (действие агента, диалог безопасного переименования), сигнал тоже сработает. Без подавления получится петля: плагин правит ссылки, срабатывает сигнал, плагин правит снова.

Нужен флаг «сейчас переименовывает плагин» вокруг собственных операций.

### 4.3. Обновление ссылок — и здесь главная тонкость

`node_refactor.prepare_node_rename` правит **и сцену, и скрипты**. Он ищет узел по старому имени **в файле сцены**.

**Проблема:** человек переименовал узел в редакторе, сцена при этом **не сохранена**. Файл на диске содержит старое имя, а редактор держит новое. Если плагин сейчас перепишет `.tscn` на диске — он столкнётся с несохранёнными правками человека в открытой сцене. Ровно этот класс конфликтов уже разбирался в плагине: авто-перезагрузка сцены теперь пропускается, если в ней есть несохранённые изменения.

**Решение:** нужен режим «обновить только ссылки в скриптах, сцену не трогать». Редактор уже держит переименование в памяти — писать его в файл не нужно и вредно.

Как это сделать — на ваше усмотрение:

1. Добавить в `node_refactor.prepare_node_rename` параметр `scripts_only: bool = False`, при котором `.tscn` не попадает в список изменяемых файлов.
2. Или сделать отдельную функцию подготовки, если так чище.

Проверьте, что `apply_prepared_node_refactor` корректно применяет результат в таком режиме — там есть проверки хешей по всем файлам, и сцена из них должна быть исключена.

### 4.4. Куда звать

Узел переименован → панель должна получить команду и вызвать серверную операцию. Используйте существующий путь, которым пользуется диалог безопасного переименования узла: он уже умеет готовить и применять такие транзакции.

Перед проверками: `Copy-Item -Recurse src\refactor_lab src\refactor_lab_backup`.

### 5.2. Проверка вживую — обязательно

Автоматически эту задачу **проверить нельзя**: она реагирует на действие человека в редакторе. Нужен открытый редактор.

1. Откройте `res://src/refactor_lab/scenes/lab_root.tscn`.
2. Выберите узел `PlayerPanel` в дереве сцен.
3. Переименуйте его в `ActorPanel` — **штатным способом Godot** (F2 или двойной клик). Именно этот путь сейчас не перехватывается.
4. **Не сохраняйте сцену.**

**Ожидается:**
- в панели появилось уведомление об обновлении ссылок;
- `scripts/lab_root.gd` содержит `$ActorPanel` вместо `$PlayerPanel`;
- сцена на диске **не изменилась**: `Select-String -Path src\refactor_lab\scenes\lab_root.tscn -Pattern 'PlayerPanel'` должен найти совпадение.

Третий пункт — самый важный. Если сцена на диске переписана при несохранённых правках в редакторе, значит режим «только скрипты» не сработал.

### 5.3. Проверка петли

Переименуйте узел дважды подряд: `PlayerPanel` → `ActorPanel` → `ActorRoot`.

**Ожидается:** ссылки обновляются один раз на каждое переименование, второго прохода нет. Повторяющиеся запросы в консоли означают, что подавление собственных переименований не работает.

## 6. Критерии приёмки

1. Переименование узла человеком в дереве сцен перехватывается.
2. `$Node`, `%Unique`, `get_node()` в прикреплённых скриптах обновляются.
3. **Сцена на диске не переписывается**, пока в редакторе есть несохранённые правки.
4. В панели появляется уведомление об обновлении ссылок.
5. Двойное переименование подряд обрабатывается корректно, петли нет.
6. Переименование узла агентом не вызывает повторного срабатывания перехвата.
7. Проверки 5.5 и 5.6 без ошибок.
8. `test_gdscript_wiring.py` — 109/109.
9. Четыре живых набора проходят с `--godot`.
10. Ни один существующий тест не сломан.

## 7. Чего НЕ делать

| Нельзя | Почему |
|---|---|
| Добавлять диалог подтверждения | решение согласовано: ведём себя как с файлами |
| Переписывать `.tscn` на диске при несохранённой сцене | конфликт с правками человека в редакторе |
| Подписываться на `renamed` без подавления собственных операций | получится петля |
| Менять способ, которым переименовывает сам плагин (агент, диалог) | задача — только перехват чужих переименований |
