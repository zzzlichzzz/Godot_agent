# ЗАДАНИЕ 5: открытая вкладка скрипта не обновляется после перехвата

**Проект:** Godot Agent — плагин ИИ-ассистента для редактора Godot 4
**Корень:** `D:\vajno\Godot\тест-плагина-ии\addons\Godot_agent\godot_agent`
**Движок:** Godot 4.6.3-stable
**Объём:** 1 день
**Зависимости:** нет. Затрагивает `agent_panel.gd`, возможно `agent_highlight.gd`

---

## 1. Симптом

Перехват переименования узлов работает: файл на диске обновляется, ссылки `$Node` в скрипте правятся, уведомление в панели появляется.

**Но если скрипт открыт в редакторе, его вкладка остаётся со старым текстом.** Человек видит `$PlayerPanel`, хотя в файле уже `$ActorPanel`. Переключение вкладок не помогает; помогает только закрыть и открыть скрипт заново.

Это опасно: редактор держит устаревший буфер, и если человек нажмёт `Ctrl+S` в этой вкладке, он **затрёт правку плагина старым текстом**.

---

## 2. Что уже есть и где

Механизм синхронизации открытого скрипта существует.

**Функция:** `_sync_open_script_with_disk(target_path)` — `agent_panel.gd:3200`

Она делает разумные вещи:

1. Проверяет, что файл существует, и читает его текст с диска.
2. Ищет открытый скрипт по `resource_path`.
3. Если вкладка содержит несохранённые правки — предупреждает и **пропускает** обновление. Это правильно: терять правки человека нельзя.
4. Иначе заменяет текст, восстанавливает позицию каретки, помечает версию сохранённой.
5. Затем вызывает `target_script.reload(true)`.

**Вызывается из девяти мест:** `agent_panel.gd:2277, 2432, 2509, 2560, 2583, 3172, 4895, 5033`. Для перехвата узлов — строка `5033`, внутри `_on_node_rename_apply_response`:

```gdscript
if changed_paths is Array:
    _refresh_changed_paths([changed_paths])
    for cp in changed_paths:
        _sync_open_script_with_disk(str(cp))
```

`changed_paths` от сервера приходит — проверено вызовом `/scene/refactor/node/apply`, поле есть. `_refresh_changed_paths` вложенные массивы разворачивает корректно. То есть функция **вызывается**, но результата не даёт.

---

## 3. Гипотеза первая: поиск редактора по индексу

Подозрительное место (`agent_panel.gd:3200` и далее):

```gdscript
var open_scripts := script_editor.get_open_scripts()
var open_editors := script_editor.get_open_script_editors()
for i in range(open_scripts.size()):
    var scr := open_scripts[i]
    if scr and scr.resource_path == target_path:
        target_script = scr
        if i < open_editors.size():
            var editor_base = open_editors[i]        # ← сопоставление по индексу
            if editor_base:
                target_code_edit = editor_base.get_base_editor() as CodeEdit
        break
```

Код предполагает, что `get_open_scripts()[i]` соответствует `get_open_script_editors()[i]`. **Это предположение нигде не задокументировано как гарантия движка.**

Проверено по кэшу API 4.6.3: метода вида `get_edited_script()` у `ScriptEditorBase` **нет**, то есть узнать «какой скрипт показывает этот редактор» напрямую нельзя. Если соответствие индексов нарушается, `target_code_edit` либо получает чужой редактор, либо остаётся `null` — и тогда открытая вкладка не обновляется, а `target_script.reload(true)` меняет только ресурс. **Симптом совпадает.**

Рядом есть рабочий образец — `agent_highlight.gd:46-48` находит редактор без арифметики по индексам:

```gdscript
var current := script_editor.get_current_editor()
var code_edit := current.get_base_editor() as CodeEdit
```

## 4. Гипотеза вторая: порядок операций

В конце функции:

```gdscript
target_code_edit.text = real_text      # сначала обновляем буфер
...
target_code_edit.tag_saved_version()

if target_script:
    target_script.reload(true)         # потом перезагружаем ресурс
```

Не исключено, что `reload(true)` возвращает буфер редактора к состоянию ресурса и сводит правку на нет. Проверьте порядок; при необходимости разделите — сначала перезагрузить ресурс, потом обновлять буфер.

## 5. Что требуется

Открытая вкладка должна показывать актуальный текст после перехвата. Ни один из подходов ниже не обязателен — выберите тот, что подтвердится проверкой.

**Что нельзя терять:**

- несохранённые правки человека в этой вкладке — сейчас они защищены, сохраните это;
- позицию каретки;
- фокус других вкладок без нужды.

**Подходы:**

1. **Найти редактор надёжно.** Вместо сопоставления по индексам перебрать `get_open_script_editors()`, у каждого взять `get_base_editor()` и связать с нужным скриптом иначе. Учтите: `get_base_editor()` может вернуть не `CodeEdit` — каст надо проверять.

2. **Через текущий редактор, как в подсветке.** Если целевой скрипт открыт и активен — использовать `get_current_editor()`, это проверенный путь.

3. **Закрыть и открыть вкладку** — предлагал автор плагина, и это допустимо. В API есть:
   - `EditorInterface.edit_script(script, line, column, grab_focus)` — открыть скрипт, при необходимости на указанной строке;
   - `ScriptEditor.script_close` — сигнал закрытия вкладки.

   Порядок такой: запомнить позицию каретки, закрыть вкладку, перечитать файл с диска, открыть заново на прежней строке. Учесть, что закрытие вкладки с несохранёнными правками недопустимо, и что переоткрытие украдёт фокус — если так выйдет, напишите об этом в отчёте.

**Проверять там же, где проявляется:** перехват переименования узла при открытом скрипте.

## 6. Как проверять

### 6.1. Тестовая среда

`res://src/refactor_lab/` — полигон. Для этой задачи:

| Что | Где |
|---|---|
| `$PlayerPanel` в скрипте | `scripts/lab_root.gd:22` |
| узел `PlayerPanel` в сцене | `scenes/lab_root.tscn:23` |
| дочерний `HealthLabel` с `parent="PlayerPanel"` | `scenes/lab_root.tscn:29` |

Перед проверками: `Copy-Item -Recurse src\refactor_lab src\refactor_lab_backup`, после — вернуть. **Копию держите вне проекта:** внутри проекта она даёт ложные ошибки Godot из-за дублей `class_name`.

### 6.2. Живая проверка — обязательна

Автоматически это не проверить: нужен открытый редактор.

1. Откройте `res://src/refactor_lab/scripts/lab_root.gd` **в редакторе скриптов**, вкладку не закрывайте.
2. Откройте `res://src/refactor_lab/scenes/lab_root.tscn`.
3. Выберите узел `PlayerPanel`, переименуйте через **F2** в `ActorPanel`. Сцену не сохраняйте.
4. **Не переключайте вкладки.** Смотрите на содержимое вкладки скрипта.

**Ожидается:** на вкладке видно `$ActorPanel`.

**Проверка на порчу данных:** после обновления нажмите `Ctrl+S` в этой вкладке и убедитесь, что файл на диске **не откатился** к `$PlayerPanel`. Это главная опасность текущего поведения.

### 6.3. Проверка с несохранёнными правками

1. Откройте скрипт, измените что-нибудь, **не сохраняйте**.
2. Переименуйте узел через F2.

**Ожидается:** вкладка не обновляется — правки человека в приоритете, в консоли предупреждение. Это существующее поведение, сохраните его.

### 6.4. Проверка многих вкладок

Откройте 3-4 скрипта в разных вкладках, переименуйте узел.

**Ожидается:** обновляется только та вкладка, чей файл изменён. Остальные не трогаются. Если обновилась чужая вкладка — это признак как раз ошибки сопоставления по индексам.

## 7. Критерии приёмки

1. Вкладка открытого скрипта показывает актуальный текст после перехвата.
2. `Ctrl+S` в этой вкладке **не откатывает** правку плагина.
3. Вкладка с несохранёнными правками по-прежнему не перезаписывается.
4. Позиция каретки не теряется.
5. При нескольких открытых вкладках обновляется только нужная.
6. Проверка 6.5 без ошибок, `test_gdscript_wiring` — 109/109.
7. Четыре живых набора проходят.

## 8. Чего НЕ делать

| Нельзя | Почему |
|---|---|
| Перезаписывать вкладку с несохранёнными правками | потеря работы человека |
| Менять логику перехвата: снимок имён, `scripts_only`, подавление | она проверена и работает |
| Трогать серверную часть | проблема на стороне редактора |
| Закрывать вкладки других скриптов | неожиданно для человека |

## 10. Почему причина не выяснена заранее

Аудит проверил, что функция вызывается и что `changed_paths` доходит до неё. Дальше начинается поведение внутри редактора Godot, которое без запущенного редактора и ручного переименования узла не воспроизводится: нужен человек, F2 и открытая вкладка.

Поэтому причина названа **гипотезой**, а не диагнозом. Подтвердите или опровергните её сами, прежде чем править код. Если обе гипотезы не подтвердятся — **не подгоняйте решение под них**, опишите в отчёте, что происходит на самом деле.
