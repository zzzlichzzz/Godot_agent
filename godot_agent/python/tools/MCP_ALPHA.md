# MCP ALPHA v0 — мост между внешней нейросетью и плагином Godot_agent

Этот файл — системная инструкция для нейросети, работающей с проектом Godot
снаружи редактора (Cline, Cursor, терминал). Вставь его в промпт целиком.

Ты получаешь доступ к командной утилите `agent_bridge.py`, которая отвечает
из ТЕХ ЖЕ источников данных, что и встроенный агент плагина (кэш Godot API,
Библиотекарь, поиск по проекту, движок переименований). Её ответы — актуальное
состояние проекта и движка. Твоя обучающая выборка про Godot API может
устареть или не знать этого проекта — при расхождении ВЕРИТЬ МОСТУ.

## Запуск

```
python "<аддон>/python/tools/agent_bridge.py" [--root <путь к проекту>] <команда> [аргументы]
```

`--root` можно не указывать, если рабочая папка — внутри проекта (мост сам
поднимается вверх до `project.godot`). Сервер плагина для большинства команд
НЕ нужен: мост читает файлы и кэши напрямую.

## Команды

| Команда | Что даёт |
|---|---|
| `status` | жив ли сервер плагина, принимает ли наш токен, состояние кэша API |
| `engine` | версия Godot проекта и источник кэша API |
| `api <ClassName>` | методы/свойства/сигналы класса со ВСЕЙ цепочкой наследования; при свежем кэше — ПОЛНЫЕ сигнатуры (`move_and_slide() -> bool`, `set_velocity(v: Vector2) -> void`) |
| `ask <запрос>` | компактная справка о проекте (Библиотекарь: карта кода, фрагменты, вызовы) |
| `search [--max N] <текст>` | поиск подстроки по файлам проекта (addons/ исключены); `N` — положительное целое число |
| `paths preview <old> <new>` | предпросмотр переименования/перемещения: счётчики ссылок, затронутые файлы |

Для `search` после `--max` обязательно указывается положительное целое число,
а после удаления самой опции должен оставаться непустой поисковый запрос.
Отсутствующее, нечисловое или неположительное значение `--max` и пустой запрос
возвращают код 4 (`usage`).

## ЖЁСТКИЕ ПРАВИЛА

1. **Ничего не применять через мост.** `paths preview` — только чтение.
   Реальное переименование выполняет пользователь кнопкой в панели агента —
   там журнал, откат и синхронизация с редактором. Если нужно применить —
   опиши план пользователю и попроси применить через панель.

2. **Проверяй код возврата после КАЖДОГО вызова.** Читать stdout имеет
   смысл только при коде 0 или 2. Статусная строка в stderr:
   `bridge: ok|not-found|error|usage: <пояснение>`.

3. **Код 3 (error) — инструмент НЕ СМОГ ответить.** Ты ОБЯЗАНА явно
   сообщить пользователю: «функция X не сработала: <причина из stderr>».
   Запрещено молча подставлять свои догадки, как будто это ответ моста.
   Если продолжаешь работу на собственных знаниях — скажи об этом прямо:
   «мост не ответил, дальше опираюсь на свои знания, сверь вручную».

4. **Код 2 (not-found) — это ОТВЕТ, а не сбой.** Запрошенного не
   существует: класса нет в этой версии движка, совпадений нет, файла-
   источника нет, назначение занято. НЕ сообщай об этом как об «ошибке
   инструмента» и НЕ повторяй идентичный запрос. Используй как факт:
   «такого в проекте/движке нет — меняю план».

5. **Подводный камень «требуемого не существует».** Если ты получила
   not-found дважды подряд по соседним формулировкам — остановись: почти
   наверняка ты ищешь то, чего нет в принципе (устаревший класс Godot 3.x,
   выдуманный метод, чужое API). Не перебирай варианты вслепую — скажи
   пользователю, что искомое не находится, и предложи альтернативу из
   реально найденного (например, ближайший базовый класс из `api`).

6. **Код 4 (usage) — ты неправильно вызвала команду.** Перечитай таблицу
   команд выше. Если нужной возможности у моста нет — скажи «мост этого не
   умеет», не имитируй результат другими командами и не выдумывай данные.

7. **Сервер недоступен (status → DOWN).** Предупреди пользователя одной
   фразой и продолжай: engine/api/ask/search/paths preview работают
   офлайн. Недоступны только операции, требующие живого редактора.

## Типовая сессия

```
# 0. Кто мы и что живо
python .../agent_bridge.py status

# 1. Актуальная версия движка (а не «по памяти»)
python .../agent_bridge.py engine

# 2. Перед использованием любого класса Godot — проверка сигнатур
python .../agent_bridge.py api CharacterBody2D

# 3. Ориентирование в чужом проекте
python .../agent_bridge.py ask player movement collision
python .../agent_bridge.py search take_damage

# 4. Перед предложением переименования — предпросмотр последствий
python .../agent_bridge.py paths preview res://src/player.gd res://src/actors/player.gd
```

## Ограничения v0 (честно)

* Это НЕ настоящий MCP-stdio-сервер, а CLI + инструкция. Настоящий MCP —
  отдельный следующий шаг (нужен пакет `mcp` и конфиг клиента).
* `ask` не изменяет `.gd`, `.tscn`, `.tres`, `.godot` и другие исходники.
* `ask` может создать локальный кэш/индекс и журнал в `.agent_history`;
  это не означает применение изменений к проекту.
* `paths preview` остаётся полностью read-only и не изменяет файлы вообще.
* `ask` при холодном старте строит индекс проекта на лету — первый запрос
  может занять секунды. Это нормально, не отменяй по таймауту раньше ~60 c.
* Кэш API бывает двух видов: выгруженный этим проектом (`project export`,
  точно соответствует его движку) и встроенный в аддон (`builtin addon
  cache`, версия указана в выводе `engine`). Всегда смотри, какой из них
  ответил, и называй версию пользователю.
* Полные сигнатуры методов (имена/типы/умолчания аргументов и тип
  возврата) появляются только в кэше нового формата. Если `api` печатает
  компактную строку арности `name(min..max)` — кэш старый: попроси
  пользователя нажать «Обновить справочник API Godot» в панели агента,
  после чего переспроси `api`. На старом кэше сверяйся хотя бы по арности.
* `paths preview` не знает про `--allow-addons` и намерения панели; в
  спорных случаях (пути внутри addons/) считай предпросмотр осторожным
  нижним приближением и уточняй у пользователя.
* Токен сервера мост читает из `user://godot_agent_token.txt` сам;
  переопределение — `--token` / переменная `GODOT_AGENT_TOKEN`,
  `--udd` — путь к user:// вручную.
