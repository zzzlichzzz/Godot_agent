# n8n: схема фабрики «Шаблон v2: Ядро + 4 канала»

Здесь версионируется рабочая схема n8n — фабрика, которая разрабатывается в
локальном инстансе (npm-установка, `http://localhost:5678`, база
`%USERPROFILE%\.n8n\database.sqlite`). Эта папка — источник схемы n8n для
выпусков обновлений плагина; все последующие изменения проходят через неё.

## Состав

    schemas/template_v2_core_4_channels.json   снимок воркфлоу (черновик)
    schemas/template_v3_economy.json           снимок копии-ветки v3 (черновик)
    scripts/export_workflow.py                 снимок базы n8n -> schemas/
    scripts/verify_snapshot.py                 сверка снимка с текущей базой
    scripts/import_workflow.cmd                импорт схемы в локальный n8n
    scripts/fork_workflow.py                   форк схемы в новую ветку (копия)
    scripts/check_no_secrets.py                скан папки на ключи и токены
    scripts/mcp_invoke.py                      вызов любого инструмента n8n MCP
    scripts/dump_execution.py                  разбор прогона: ноды, ошибки, данные
    scripts/token_report.py                    токены прогона: вызовы и usage моделей
    scripts/README.md                          шпаргалка по этим скриптам

Текущий снимок: id `v81fH05KY5uKUNK0`, 212 узлов, active=true (вебхуки живут),
versionId печатается при экспорте (последний на 12.10.2026: `b39bef85-c6e1-41fe-8df5-3c74f5ed98cf`).
Файл держит только состав данных схемы (id/name/nodes/connections/settings/meta);
versionId, даты и прочие рантайм-поля не пишутся, чтобы не шуметь в
истории git. Скрипт экспорта печатает актуальный versionId при каждом
снимке.
Поля `text` у инструментов-субагентов «Поисковик (субагент)» и «Поисковик (API)»
построены на `$fromAI('input', ...)`: это и строит схему тула (модель обязана
передать поле `input`), и читает её значение из аргументов вызова. Без
`$fromAI` LLM вызывала поисковик без аргументов — «No prompt specified»
(исправлено 11.10.2026).
С 11.10.2026 в схеме есть субагент-инструмент «Поисковик (субагент)» у
Аудитора (4 ноды: agentTool + своя модель + «MCP: руки (Поисковик)» и
«MCP: инструменты Godot (Поисковик)», только чтение). Паттерн проверен
живым прогоном (тестовый workflow «ZZ Прототип: Поисковик», execution 47).

С 11.10.2026 канальные «Планировщик X» и «Поисковик (X)» стоят у всех четырёх каналов (по образцу прототипа API): 10 нод на канал — планировщик с памятью planner-<ch>-*, своя модель и поисковик с личными руками (mcpClientTool :8010 + инструменты Godot :8000). Итоговое задание планировщика («ЗАДАЧА КАНАЛУ: …») подхватывает «X: промпт (память)» (фолбэк — task_<ch> из шины), в системных промптах каналов есть строка-подсказка про «Поисковик (<X>)». Сторож волн: «Шина: стартовый пакет» штампует wave_start_ms, «Агрегатор каналов (ждать всех)» принимает только отчёты текущей волны (createdAt ≥ wave_start_ms − 2 с) — ложный agg_done по отчётам прошлых волн вылечен.

Каналы — четыре равных исполнителя одной задачи; различаются только манерами
(Браузер — парсинг страниц с минимумом запросов; API — стандартный агент;
Редактор — действия как человек в редакторе Godot; MCP — MCP-инструменты для
внешних агентов). Функционал у всех одинаковый: «руки» (:8010), инструменты
Godot (:8000, включая мост записи write_preview → write_apply → write_rollback)
и личный «Поисковик (X)». С 11.10.2026 «MCP: инструменты Godot» подключён всем
четырём каналам.

С 11.10.2026 «Распределитель плана (по каналам)» приведён к той же концепции:
раздаёт этапы по манерам (жёсткой матрицы «правки кода — только MCP, тесты —
только API/MCP» больше нет), один этап можно дробить между каналами ради
параллельной работы; формат ответа (work_<ch>/task_<ch>, правило маркеров из
вердикта, «Правила полей») не менялся.

## Безопасность (ключи нейросетей)

* В снимке НИКОГДА не должно быть ключей и прочих секретов. n8n экспортирует
  только ССЫЛКИ на креденшелы (`credentials: {id, name}`); значения ключей
  хранятся в базе n8n и в файл не попадают.
* Скрипт экспорта читает таблицу `workflow_entity` только для чтения; таблица
  `credentials` не читается вообще.
* Перед каждым коммитом: `python -B scripts/check_no_secrets.py` — ожидаем
  «ошибок 0». Предупреждения о длинных строках проверяются глазами.
* Локальные ключи и секреты в этой папке не хранить (см. `.gitignore`).

## Обновить снимок (n8n -> репозиторий)

1. В редакторе n8n сохранить правки (снимок берётся из сохранённого черновика).
2. Из папки n8n выполнить:

       python -B scripts/export_workflow.py

   Скрипт мгновенно перезапишет `schemas/` и напечатает id/имя/узлы/versionId.

Эквивалент официальной CLI-командой (в PowerShell шим `n8n` может блокироваться
политикой — тогда используйте `n8n.cmd` из `%APPDATA%\npm`):

    n8n.cmd export:workflow --id=v81fH05KY5uKUNK0 --output=schemas\template_v2_core_4_channels.json

Она выгружает шире (shared/triggerCount/versionCounter/даты) — для снимка в
git достаточно вывода первого скрипта; сверка nodes/connections/settings
между двумя способами выполнялась и совпала.

Проверить, что снимок в репозитории ещё совпадает с базой (без перезаписи):

    python -B scripts/verify_snapshot.py

Код возврата 0 — снимок идентичен текущему черновику n8n; 1 — файл разошёлся
с базой (были правки в редакторе после снимка — сделайте новый экспорт).

## Поставить схему в n8n (репозиторий -> n8n)

* Обновить существующий воркфлоу: открыть его в редакторе n8n ->
  меню (⋮) -> `Import from File...` -> выбрать файл из `schemas/`.
* Импорт CLI (например, на чистый инстанс):

      scripts\import_workflow.cmd

* После переноса назначить креденшелы и таблицы заново — чек-лист в разделе
  «Перенос на другой инстанс» ниже. Значения ключей вводит сам пользователь
  в n8n (Settings -> Credentials) — в git они не попадают.

## Перенос на другой инстанс (что настроить руками)

Логика схемы (212 узлов) самодостаточна, но файл ссылается на объекты
конкретного инстанса — на чистом n8n их нужно создать и выбрать заново:

1. **Креденшелы.** Все 19 нод «Модель (…)» используют credential типа
   `OpenAI API` (у авторов — «Cline API (ClinePass)»): OpenAI-совместимый
   Base URL + ваш ключ. Создайте свой креденшел и выберите его в каждой из
   11 нод. Имена моделей прописаны в нодах
   (`cline-pass/deepseek-v4.1-flash` — 17 шт., `cline-pass/mimo-v2.6-flash` —
   «Сборщик» и «Документатор»); при другом провайдере замените на свои.
2. **Data tables (2 шт.).** Создайте таблицы с такими же колонками и заново
   выберите их в нодах Data Table (id таблиц локальны для инстанса):
   * «Память чатов агентов» (22): session, role, content — string;
   * «Отчёты цикла» (3): kind, status, task, audit, plan, user_edits,
     execution_id, resume_url — string; ring — number; created_at — date.
3. **MCP-серверы (ноды MCP Client Tool).** «MCP: инструменты Godot» и
   «MCP: инструменты записи (Документатор)» → `http://127.0.0.1:8000/mcp`;
   «MCP: руки (терминал, файлы, поиск)» → `http://127.0.0.1:8010/mcp`.
   На новой машине поднимите эти серверы (MCP-сервер плагина Godot) или
   замените URL на свои.
4. **Точки входа:** чат «Чат (общий вход)» — панель Chat в n8n; вебхуки
   POST `browser`, `api`, `editor`, `mcp` (полный URL нода покажет после
   импорта: `<хост>/webhook/<path>`).
5. **Версия n8n:** проверялось на 2.42.3 — нужна поддержка Data Table и
