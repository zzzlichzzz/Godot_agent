# Отложено

Задачи полировки перед окончательной стабилизацией текущего этапа.

## Откат изменений — что осталось

- **Откат недоступен после переоткрытия чата.** Сообщения о применённых правках («Изменения успешно внесены в…») вообще не сохраняются в транскрипт (`main.py` зовёт `_remember` только для ответов модели), поэтому после переключения чатов эти облачка исчезают вместе с кнопками отката. Раньше кнопки на восстановленных облачках были, но откатывали не то. Чтобы вернуть работающий откат в истории, надо сохранять в транскрипт и само сообщение о правке, и её `history_entry_id` (поле в `chat_store.append_transcript`), а `_render_transcript` — передавать адрес в `add_agent_message`.
- **Откат отдельного шага плана.** Сервер уже отдаёт `history_entry_id` в ответе `/chat/plan/step`, но панель показывает шаги простыми строками (без карточек), и откат плана идёт целиком по `chain_id`. Если понадобится откат одного шага — данные для этого уже есть.
- Журнал изменений общий на проект, а не на чат (`history_manager`), и `MAX_ENTRIES = 50`. Адресный откат теперь честно отказывается работать, если тот же файл позже правил агент, но старые записи всё равно вытесняются по лимиту — тогда кнопка отвечает «изменение вытеснено по лимиту истории».

Правки в `.spec` живут до следующей сборки и теряются молча — именно так однажды уже пропал список новых модулей. Источник истины — флаги в `.bat`; согласованность проверяет `tests/test_pyinstaller_spec.py`.
- **Живая проверка на настоящем ключе OpenRouter.** Весь код закрыт офлайновыми тестами (локальный HTTP-сервер вместо провайдера), но реального обмена с OpenRouter ещё не было. Проверить по порядку: сохранение ключа, обновление списка моделей, кнопку проверки подключения, первый чат, чтение файла, план из нескольких шагов, кнопку «Стоп» посреди ответа, поведение при исчерпании суточного лимита.
- **Проверить панель в самом Godot.** Godot на машине сборки отсутствовал, поэтому синтаксис GDScript проверялся статически (`tests/test_gdscript_wiring.py`: ключи локализации, обработчики сигналов, виды запросов, наличие токена во всех запросах), а не запуском. Экран настроек API ни разу не был отрисован — посмотреть его в узком и широком доке, на русском и английском.
- **Прокси через настоящий прокси-сервер.** Логика есть и покрыта тестами (локальные адреса прокси не используют, TLS не отключается), но живой прогон через прокси во Франции к `generativelanguage.googleapis.com` не делался. Помнить: адрес API у Gemini — другой хост, чем у сайта.
- **Проверить бюджеты токенов на реальных ответах.** `API_CONTEXT_WINDOW = 32000`, `API_HISTORY_BUDGET = 16000`, `API_MAX_TOKENS = 8000` — предположения, а не измерения. Связь между ними обязательна (провайдер отклоняет запрос, если `prompt_tokens + max_tokens` больше окна) и проверяется тестом; сами числа стоит уточнить по факту.
- **Пересмотреть расположение расхода токенов.** Сейчас строка `· 1234 → 567 tok · Σ 12345 · 4 запр.` добавляется под ответ модели прямо на сервере (константа `SHOW_USAGE_IN_CHAT` в `api_backend.py`). Так не потребовалось менять панель, но правильнее это место — `AgentStatusBar`. Тогда же можно локализовать: сейчас строка намеренно почти без слов, потому что сервер про выбранный язык не знает.
- **Кэширование промпта (prompt caching).** Мега-промпт уходит системным сообщением в КАЖДОМ запросе. У части провайдеров есть кэш префикса, который снижает его цену в разы. Половина условия уже выполнена: внутри одного хода системный блок неизменен (кэшируется в `STATE["api_system_cache"]`). Осталось вынести изменчивое (свежее дерево после `list_files`, сводку внешних правок) из системного блока в отдельное сообщение, чтобы префикс не менялся и между ходами.
- **Автоматическое продолжение при `finish_reason == "length"`.** Сейчас факт обрезки известен точно и показывается пользователю, но продолжение не запрашивается — модель по-прежнему должна сама прислать следующую часть через `"continues": true`. По API это можно делать автоматически.
- Мелочь: `chat_store._load` читает и разбирает весь файл чатов вместе с транскриптами на каждое обращение, а за один ход пользователя это происходит несколько раз (выбор бэкенда, проверка вида чата, запись). Пред-существующая неэффективность, но с работой по ключу обращений стало больше. Лечится кэшем записи чата на время запроса.

## Безопасность

- Шифрование ключа API привязкой к аккаунту ОС: DPAPI (`CryptProtectData` через `ctypes` + `crypt32.dll`) на Windows, keychain/libsecret на остальных. На первом этапе решено обойтись хранением открытым текстом ЗА пределами проекта — это отраслевая норма, и добавление шифрования позже ничего не ломает. Защищает от бытовых утечек (случайный коммит, синхронизация AppData в облако, передача папки другому человеку), а не от малвари под тем же аккаунтом. Свой AES с зашитым в код ключом не писать — это хуже открытого текста из-за ложной уверенности.
- Честная граница токена на порту `5000` (`server_auth.py`): токен лежит в файле, читаемом тем же пользователем, поэтому от программы под той же учётной записью он НЕ защищает. Закрывает чужую учётную запись, случайные обращения и панель другого проекта. Если понадобится настоящая изоляция — это уже уровень ОС (отдельная учётная запись для сервера, sandbox), а не токен. Не описывать его в документации как защиту от вредоносного ПО.
- Первое обращение к серверу привязывает его к проекту (trust on first use). Окно между запуском сервера и привязкой — миллисекунды, но оно есть. Если когда-нибудь понадобится закрыть и его, правильный путь — передавать токен серверу при запуске процесса, а не через файл.

## Оптимизация API-режима (после первой рабочей версии ключей)

- Насыщать первый запрос **контекстом редактора** вместо разведки: открытый скрипт, открытая сцена, выделенный узел. Это детерминированные данные, а не догадки, и они часто снимают необходимость в `read_file`/`ask_librarian` целиком. Автозапуск Библиотекаря по сырому тексту запроса пользователя НЕ подходит: его индекс рассчитан на англоязычные запросы в терминах кода, а перевод намерения в такие термины — работа модели.
- Поднять `max_tokens` и замерить, насколько перестаёт срабатывать многочастная машинерия (`continues: true`, `MAX_PLAN_PARTS`, `MAX_CONTENT_PARTS`). В веб-интерфейсах она нужна из-за потолка длины ответа, по API потолок задаём мы. Каждая несостоявшаяся часть — минус один запрос. Начальное значение `API_MAX_TOKENS = 16000` выбрано «с запасом» и на живых ответах не проверялось.
- Пересмотреть `MAX_PLAN_STEPS = 12` и порог выбора плана: оба подобраны под потолок вывода веб-интерфейса. Обсудить повторно, когда появится рабочая реализация API и накопится реальная статистика.
- Держать в голове главный принцип API-режима: лишний ход заново пересылает весь мега-промпт и всю историю, поэтому меньше ходов = меньше и запросов, и токенов. Цель — **минимум ходов**, а не максимум самостоятельности агента.

## Локальные модели через llama.cpp (этап ПОСЛЕ API-ключей)

- Свой инференс не писать. Использовать `llama-server` из llama.cpp — один исполняемый файл, который сам отдаёт OpenAI-совместимый HTTP.
- Подключать тем же бэкендом, что и API-ключи: `base_url = http://127.0.0.1:<порт>/v1`, заголовок `Authorization` не нужен. Отдельной ветки логики в агенте не требуется — это ещё один провайдер в реестре.
- Модели и бинарники в репозиторий не кладём: докачка по кнопке из панели, запуск через `subprocess`. Паттерн автозапуска и поиска исполняемого файла уже готов в `agent_server_link.gd`.
- GPU — главная сложность. Начинать с Vulkan-сборки: одна сборка покрывает AMD/NVIDIA/Intel вместо отдельных CUDA/ROCm/Metal. CPU-сборка остаётся гарантированным запасным путём. В панели показывать, какой backend выбран и сколько слоёв ушло на GPU.
- Прослойка настройки обязательна: пользователь не должен видеть флаги llama.cpp. Свой упрощённый экран — модель из проверенного списка, размер контекста, слои на GPU (авто/вручную), кнопка проверки. За ориентир брать удобство готовых LLM-оболочек, но интерфейс делать в стиле панели, а не копировать.
- Слабая модель будет ломать формат действий чаще: до включения локального режима укрепить терпимость `parse_action_json`/`coerce_action_schema` (корпус сбоев в `tests/parser_corpus/`) и пересмотреть `MAX_ACTION_FIX_RETRIES`. Основная защита от неверного кода — не парсер, а линт-барьер (`gd_lint`, `gd_api_check`, `tscn_lint`); усиливать в первую очередь его.
- Порядок работ: сначала API-ключи на бесплатных tier (там модель достаточно сильная, чтобы отладить историю диалога, priming каждым запросом и Markdown→BBCode на нормальном материале), локальный режим — после, как ещё один `base_url`.

Не трогать, пока не появится реальный сбой в телеметрии; при желании лечится точечно (пропуск тройных кавычек) без замены на парсер.

## Улучшение исправлений кода агентом: санитизация и компиляционная проверка GDScript 4

**Статус:** отложено, требуется отдельное проектирование и интеграция.

**Цель:** уменьшить число синтаксических галлюцинаций слабых локальных моделей и не применять сгенерированный GDScript к проекту, пока он не прошёл детерминированную обработку и проверку Godot.

### Предлагаемый трёхуровневый пайплайн

```text
[ LLM: Bonsai 27B / другая локальная модель ]
                         |
                         v
[ 1. Детерминированный санитайзер ]
  - исправление известных примесей C++/JavaScript;
  - нормализация ограниченного набора конструкций GDScript;
  - формирование журнала выполненных замен.
                         |
                         v
[ 2. Godot Headless: компиляционная проверка ]
  godot --headless --check-only --script <temp.gd>
  - разбор stdout/stderr;
  - извлечение строк и типов ошибок.
                         |
             +-----------+-----------+
             |                       |
             v                       v
      [ Ошибок нет ]          [ Ошибки компиляции ]
             |                       |
             v                       v
  [ Применить в проект ]      [ 3. Micro-Fix через LLM ]
                               - только проблемный блок;
                               - сообщение компилятора;
                               - минимальный ответ модели;
                               - повторная проверка слоем 2.
```

Для Micro-Fix нужен конечный лимит повторов. После исчерпания лимита изменение не применяется, а пользователю показываются исходная ошибка Godot и итоговый кандидат.

### Карта типичных ошибок модели

| Ошибка модели | Синтаксис или подход в GDScript 4 | Предлагаемое действие |
| :--- | :--- | :--- |
| `// Comment` | `# Comment` | Заменять только однозначно распознанный комментарий, не оператор целочисленного деления `//`. |
| `array.length` | `array.size()` | Точечная замена `.length` на `.size()`. |
| `dict.contains(k)` | `dict.has(k)` | Точечная замена `.contains(` на `.has(`. |
| `@export class X extends RefCounted` | `class_name X extends RefCounted` либо локальный `class X` | Выбирать форму по контексту объявления, а не простой заменой аннотации. |
| `virtual func foo(): void = {}` | `func foo() -> void:` + тело | Удалить `virtual`, нормализовать возвращаемый тип и создать корректное тело (`pass`, если это заглушка). |
| `@onready` или `_ready()` в `RefCounted` | Инициализация через `_init()` или обычное поле | Исправлять только после проверки базового типа и назначения метода/поля. |
| `Array<Type>` | `Array[Type]` | Заменять синтаксис типизированного массива. |
| `Set<Type>` | В GDScript нет встроенного `Set`; обычно используется `Dictionary` | Требуется контекстная замена, автоматическая regex-правка небезопасна. |
| Блоки `{ ... }` | Блок после `:` с отступами | Нужен структурный разбор блока; удаления скобок недостаточно. |

### Ограничения детерминированного санитайзера

- Нельзя глобально заменять `//` на `#`: в GDScript 4 `//` является оператором целочисленного деления.
- Нельзя надёжно преобразовать фигурные скобки в блоки с отступами построчными regex-заменами.
- Нельзя без анализа контекста заменять любой `_ready()` на `_init()`: методы имеют разный жизненный цикл.
- Удаление `@onready` с поля может изменить момент вычисления выражения и сломать зависимости от дерева сцены.
- Замены не должны затрагивать строки, многострочные строки и комментарии.
- Каждое преобразование должно возвращать журнал замен; спорные преобразования лучше передавать в Micro-Fix.
- Перед интеграцией нужен корпус входов с валидным и невалидным GDScript, чтобы санитайзер никогда не портил уже корректный код.

Практический вариант первого этапа: начать только с безопасных лексических замен `.length` и `.contains(` вне строк/комментариев. Контекстные преобразования добавить позже, после тестов на реальных ответах моделей.

### Черновой Python-модуль

Ниже сохранён исправленный по форматированию эскиз исходного предложения. Это основа для прототипа, а не готовый к подключению production-код: перед использованием нужно устранить перечисленные выше ограничения regex-обработки.

```python
import os
import re
import subprocess
import tempfile
from typing import Optional, Tuple


class GDScriptSanitizer:
    @staticmethod
    def sanitize(code: str) -> str:
        clean_lines = []

        for line in code.splitlines():
            # Только полноформатный C++/JS-комментарий. Inline `//` может быть делением.
            line = re.sub(r"^(\s*)//(.*)$", r"\1#\2", line)
            line = re.sub(r"\.length\b", ".size()", line)
            line = re.sub(r"\.contains\(", ".has(", line)
            line = re.sub(r"@export\s+class\b", "class", line)
            line = re.sub(r"\bvirtual\s+func\b", "func", line)
            clean_lines.append(line)

        result = "\n".join(clean_lines)

        if "extends RefCounted" in result:
            result = re.sub(
                r"@onready\s+func\s+_ready\(\)",
                "func _init()",
                result,
            )
            result = re.sub(r"func\s+_ready\(\)", "func _init()", result)
            result = re.sub(r"@onready\s+", "", result)

        return result


class GodotLinter:
    def __init__(self, godot_bin_path: str = "godot"):
        self.godot_bin = godot_bin_path

    def check_syntax(self, script_content: str) -> Tuple[bool, Optional[str]]:
        """Return (is_valid, compiler_output)."""
        with tempfile.NamedTemporaryFile(
            mode="w",
            suffix=".gd",
            delete=False,
            encoding="utf-8",
        ) as temp_file:
            temp_file.write(script_content)
            temp_path = temp_file.name

        try:
            result = subprocess.run(
                [
                    self.godot_bin,
                    "--headless",
                    "--check-only",
                    "--script",
                    temp_path,
                ],
                stdout=subprocess.PIPE,
                stderr=subprocess.PIPE,
                text=True,
                timeout=5,
                check=False,
            )
            output = f"{result.stdout}\n{result.stderr}".strip()
            has_error = (
                result.returncode != 0
                or "SCRIPT ERROR" in output
                or "Parse Error" in output
            )
            return (False, output) if has_error else (True, None)
        except subprocess.TimeoutExpired:
            return False, "Linter timeout"
        except FileNotFoundError:
            return False, f"Godot binary not found: {self.godot_bin}"
        finally:
            if os.path.exists(temp_path):
                os.remove(temp_path)
```

### Шаблон Micro-Fix-промпта

Ориентир по размеру ответа модели: 200–300 токенов, если проблемный блок помещается в этот бюджет. Модели передаётся не весь файл, а минимальный самодостаточный блок с необходимыми объявлениями типов.

```text
СИСТЕМНЫЙ ПРОМПТ:
Ты — точечный исправитель GDScript 4. Исправь конкретную ошибку,
которую сообщил компилятор Godot. Верни только исправленный блок
кода без объяснений и Markdown-разметки.

КОНТЕКСТ:
Код блока:
{failed_code_block}

Ошибка компилятора Godot 4:
{compiler_error_output}

ПРАВИЛА:
- Исправляй только строки, связанные с ошибкой.
- Не меняй публичный контракт функции без необходимости.
- Сохраняй типы и синтаксис Godot 4, включая StringName и Array[Type].
- Не добавляй отсутствующие API Godot.
```

После ответа Micro-Fix блок должен быть вставлен в исходный кандидат и снова пройти полный цикл компиляционной проверки. Нельзя применять ответ Micro-Fix напрямую.
