# fixtures/ — два вида фикстур

Фикстуры отвечают на разные вопросы, поэтому лежат в разных корнях. Смешивать их
нельзя: корпус инструмента проверяет **поведение механики**, корпус формата —
**разбор**, и оба сняты с эталона (R-07), а не написаны «по памяти».

## 1. `corpus/<область>/<фича>/` — корпус инструмента

Что проверяет: ответ старого агента на конкретный вызов механики.

- один кейс = один JSON-файл: `{id, tool, fixture, args, expect}`;
- `fixture` — имя проекта из `fixtures/projects/<имя>/` (у кейса свой проект);
- `expect` — снятый эталоном результат либо `{"ok": false, "kind": "..."}`;
- `manifest.json` — дата съёмки, хеш эталонного файла и хеши кейсов.

Снимается только `tools/snapshot_record.py` (он вызывает эталон отдельным
процессом с `-B`); сравнивается `tools/snapshot_diff.py` и `selfcheck.py`.
Кейсы руками не правятся: расхождение — баг переноса или строка в
`docs/deviations.md`.

Пример: `fixtures/corpus/code_intel/usages/`, `fixtures/corpus/code_intel/analyze_rename/`,
`fixtures/corpus/project_text/search/`, `fixtures/corpus/code_intel/functions/`,
`fixtures/corpus/editing/write_preview/` (16 кейсов, фикстура
`projects/rename/`: объявление, наследник, вызов по имени, закрытый аддон),
`fixtures/corpus/editing/write_apply/` (14) и `fixtures/corpus/editing/rollback/`
(4).

Кейс записи описывает **сценарий** (поле `scenario`, например `preview_apply`):
`write_apply` требует `plan_id` от предпросмотра, поэтому ожидание — итоговые
байты файлов (`{files: {rel: sha256}}`), а не ответ одного вызова.

## 2. `parity/<формат>/` — корпус формата

Что проверяет: что новый разборщик формата даёт **ту же структуру**, что эталонный
`parse` (смещения, строки, колонки, закрытость строк).

- входы — реальные файлы формата (`*.gd`), рядом `expected.json` с эталонным
  разбором каждого файла;
- хеши и дата — в самом `expected.json`;
- снимается вручную с эталонного парсера **до** первой строки нового кода,
  проверяется `tests/py/formats/test_gdscript_parity.py`.

Пример: `fixtures/parity/gdscript/` (8 файлов: объявления, строки, вложенный
класс, комментарии, аннотации, типизированные коллекции, BOM, CRLF).

## 3. `projects/` — проекты для вызовов

`fixtures/projects/<имя>/` — минимальный Godot-проект (`project.godot` +
несколько `.gd`), на котором запускаются корпуса и `probe`. Проект — не корпус:
он переиспользуется несколькими механиками (например, `projects/usages/`
обслуживает и `usages`, и `analyze_rename`).

## Чего здесь не бывает

- секретов, токенов, абсолютных путей (проверяет `snapshot_record.py`);
- `__pycache__` и `.pytest_cache` (тесты гоняются с `-p no:cacheprovider`);
- кейсов, написанных «под новый код»: корпус снимается с эталона.
