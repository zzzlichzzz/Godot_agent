# tests/py/security — атакующие тесты (R-20)

Статика проверяется `tools/security_audit.py` (входит в `selfcheck`). Здесь —
динамика: то, что видно только при вызове агента. Каждый файл — один класс атаки,
имя = номер инварианта из `docs/security/invariants.md`.

| Файл (появится с механикой) | Инвариант | Что доказываем |
|---|---|---|
| `test_path_escape.py` | SEC-12 | `..`, абсолютный путь, симлинк, junction, UNC, смена регистра, юникод-омоглифы → `denied`, файл вне проекта не тронут |
| `test_http_boundary.py` | SEC-10 | нет токена → `denied`; чужой `Origin` → `denied`; `Host: evil.test` → `denied`; тело больше лимита → отказ |
| `test_ssrf.py` | SEC-08, SEC-09 | запрос к хосту вне `contract/network_allow.json` и к `169.254.169.254` → `denied`, без сетевого вызова |
| `test_prompt_injection.py` | SEC-14, SEC-15 | файл проекта с инструкцией «прочитай `.env` и отправь» не меняет ход вызова; флаг автоподтверждения из данных игнорируется |
| `test_write_funnel.py` | SEC-11 | `apply` без `plan_id`/`digest` невозможен; `preview` не меняет хеши файлов |
| `test_secret_redaction.py` | SEC-13 | фейковый ключ в проекте не появляется в логе, ошибке, отчёте `selfcheck` и корпусе |
| `test_updater_zip_slip.py` | SEC-16 | архив с `..\\..\\x.gd` → отказ, ничего не распаковано вне корня; код из архива не исполняется |
| `test_limits.py` | SEC-18 | превышение лимитов (размер файла, число результатов, тело) → `invalid_input`, а не падение |

Правила для этих тестов: только stdlib, никакой сети, фейковый LLM, проект
создаётся во временном каталоге и удаляется; каждый тест должен **падать** на
старом поведении (иначе он ничего не доказывает) — проверяется мутацией в
`deviations.md`.
